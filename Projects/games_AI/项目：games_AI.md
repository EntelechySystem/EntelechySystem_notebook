# 立项边界与接口契约

> 本节的边界裁定与接口契约源自 CSL `games_AI/README.md`（2026-09-02 成文，

## 与 `games_explore` 的边界（已裁定：分别立项，不合并）

二者是**正交的两层**，不是同一层的两半：

| | `games_explore`（CSL 侧） | `games_AI`（本 vault） |
|---|---|---|
| 问的问题 | **What is the game**——规则怎么设计才平衡 | **How to play it well / like someone**——AI 怎么下 |
| 层次 | 对象层（规则、棋盘、子力） | 实现层（搜索、评估、风格） |
| 产出 | 变种规格（供数值优化/玩法仿真） | AI 行为（性格/风格/教学/观赏性） |

正交性判据：

- **同一算法可服务多个对象**：Max^n 既能下 6 人六芒星中国跳棋，也能下 4 人国际象棋 → 算法层不该按对象拆分
- **同一对象可用多个算法验证**：N×N 大棋盘既可用 Minimax 也可用 MCTS 检验平衡性 → 对象层不该按算法拆分

## 与算法层（CSL `演化博弈`）的关系

算法谱系与选型判据由 CSL `演化博弈` 提供（Max^n / Paranoid / BRS / ISMCTS / MARL / LLM 元控制器）。
本项目的增量在「风格注入机制」（风格项加在哪一维、如何从采样偏置/rollout 注入），
详见 [[memo-多人博弈算法会话精读-20260902]] §1.1。

## 信息结构接口契约（本 vault ↔ CSL games_explore）

分开立项的代价靠契约互锁。与 `games_explore` 的契约只有一个**必需字段**：

| 方向 | 契约 |
|---|---|
| `games_explore` → 本项目 | 每个棋类变种的对象规格**必须声明信息结构**：玩家数 N、信息结构（I0 完全 / I1 不完全 / I2 不对称+欺骗）、是否零和、对称性程度 |
| 本项目据此选型 | **I0 且 N=2** → Minimax + α-β，风格项加在评估函数<br>**I0 且 N≥3** → Max^n + Paranoid/BRS，⚠️ 风格注入机制需重新设计<br>**I1** → 传统 Minimax 基本失效，转 ISMCTS + DRL，风格从采样偏置或 rollout 策略注入 |

> ⚠️ 已知缺口：`games_explore` 的《大棋盘国际象棋》变种文档尚未补「信息结构」声明栏（待 CSL 侧补）。
