## 〇、一句话总结

用户以国际象棋为案例，逐步构想并论证了一套**「可解释棋类 AI」框架**：
**系统一**（棋子间威胁/保护构成的有向关系网络评估，图论化、符号化、可解释）
与**系统二**（Minimax/α-β/MCTS 搜索）分工；并由此延伸出**性格赋予**（评估权重偏置、
风险系数、风格模板）、**教学式 AI**（可调 level、故意留破绽）、**观赏性对弈**
（LLM 指挥官 + 引擎执行者）三张产品面——本质是把"棋类 AI"从"赢棋机器"改造为
**有性格、可解释、可教学、可观赏的游戏 AI**。

## 一、会话脉络（五阶段）

### 阶段 1｜算法地基：为什么传统引擎不直接建有向关系网络（Pair 1–3）

- **传统算法体系**（Pair 1）：Minimax + α-β 剪枝 + 静态评估函数，辅以渐进深化、
  静态搜索（Quiescence Search）、置换表、开局库/残局库；现代引擎=NNUE / MCTS 路线。
- **评估函数要素**（Pair 2）：子力价值（兵1 马/象3 车5 后9）、兵型、位置分、王安全、
  机动性、保护/威胁关系；加权求和输出（厘兵）。
- **关键提问**（Pair 3）：为什么不用敌我威胁+保护构成的**有向关系网络**做评估？
  助手给出经典工程回答：① 评估在搜索中被调用数百万次，图构建太慢；
  ② **搜索树本身就是威胁关系的动态展开**，静态图是冗余；
  ③ 静态威胁评估不可靠（区分不了即时/远期威胁）；
  ④ 图关系增量更新困难；⑤ "苦涩的教训"——更多搜索 > 更复杂评估。
  → **为后续"系统一"的价值定位埋下伏笔**。

### 阶段 2｜"系统一"构想与认知科学定位（Pair 4–6）

- **用户坚持**（Pair 4）：算力已足够支撑"几步内"的动态有向威胁网络，
  并把**暴露王/棋子变动**纳入动态关系网络；关注**认知科学角度**人类棋手分层
  （入门 vs 高手）分别适合快搜简评 vs 慢搜复评，以及**符号可解释性 vs 神经网络黑箱**。
- 助手回应：全局面动态网络在工程上低效（组合爆炸），但**作为局部静态搜索/战术验证很合理**；
  认知上入门者=系统2（显式深搜+简评估），高手=系统1（模式识别+复杂评估，偶尔精准搜索）；
  要可解释、符合教学逻辑 → **传统/启发式评估（含动态关系特征）优于神经网络**。
- **系统一 = 可解释评估、系统二 = 搜索** 的框架由此确立；
  且系统一**天然适配任意棋类/变种**（图结构通用），系统二则通用逻辑骨架（Pair 6）。

### 阶段 3｜从"系统一"到游戏角色性格（Pair 7）

- 用户：用系统一设计不同**下棋风格角色**——双马攻势型、后单杀刺客、开局推兵狂、
  铁壁防御、嗜血进攻，甚至"欺软怕硬"动态切换。
- 助手：本质是**对评估函数做定向偏置注入**（Feature Weight Amplification /
  Risk/Reward Multiplier / 动态性格切换）；系统二保底、系统一戴"有色眼镜"；
  与《文明》《全面战争》《炉石》NPC 设计同思路；建议先做**角色性格配置表（JSON/YAML）**。
  → 这正是 YG_design 既有「废材棋牌 AI」想法与 [[memo-游戏AI角色与性格设计-20260724]] 的技术底座。

### 阶段 4｜原理深挖与自我调参闭环（Pair 8–13）

- 搜索与动态网络的关系（Pair 8–9）：α-β 搜索即动态威胁展开；与 RL 动态规划的联系与区别；
  现代非 ML 棋类算法主流仍是 α-β + 更强评估。
- 评估参数校准（Pair 10–11）：子力价值/位置表本质是**参数**（原由专家设定）；
  用户指出 **"系统一"才更符合棋盘最初始的参数设定 + 人类认知直觉**，且可解释。
- 放入 RL（Pair 12–13）：AlphaZero 的 reward 如何设计；**系统一能否作为 reward / 评估信号**；
  **系统一的参数本身也应通过自我对弈闭环来调优**（Pair 13）：
  - 路径一：系统一可微（如 GNN）→ 端到端反向传播（≈AlphaZero，但强归纳偏置、可解释）；
  - 路径二：系统一符号化（图论公式 + 权重）→ 遗传算法 / 线性回归 / TD(λ)（1959 Samuel 路线）。
  - **终极形态**：动态关系网络（评估）+ 搜索（因果推演）+ RL（参数调优）三者自洽进化。

### 阶段 5｜文献检索（Pair 14–16）

- 检索与"可解释动态关系评估""系统一 as reward"类似/超越的开放研究；
- 方向 1：**势函数奖励塑形（Potential-Based Reward Shaping）** 等 reward 塑形；
  方向 2：以国际象棋为例的专用研究；按"通用研究 / 专用研究"两级分类。

### 阶段 6｜memo 导出与性格/教学/观赏三面展开（Pair 17–23）

- Pair 17–19：导出 **3 份 memo**（① 知识点与概念深入浅出；② 系统一为主系统二为辅、
  游戏 AI 角色性格设计；③ 系统一用在强化学习 reward），并**修正补全"系统一"详细细节**
  （威胁边/保护边/牵制边/控制边、王暴露分析、静态+动态层面、图论指标）。
- Pair 20：不以"赢棋"为目的——**传统/DL/RL 三路线赋予风格**；
  **"求输 AI"**（日本研究）：评估取反 / 翻转标签 / 翻转奖励，但要"**优雅的输**"
  （选次优但不送子）。
- Pair 21：**大师 = 能任意调 level + 故意留破绽**；多邻国奥斯卡机制澄清
  （搜索深度限制 + 走法采样 + ELO 分段，非简单随机扰动）；
  **教学式 AI**（故意留破绽、教学时刻、学习窗口）；风格奖励塑形不稳定
  （奖励冲突/风格漂移/整活过度）→ **符号 AI × 深度 RL 混合**四方案：
  ① 符号硬约束 + NN 决策；② 风格嵌入（Style Embedding / one-hot 条件输入）；
  ③ **分层架构**（符号层管风格 → 策略过滤层 → RL 层管战术，最有前景）；
  ④ 风格模板 + 风格对抗训练（"双板斧 vs 长枪"斗兽场）。
- Pair 22：**LLM 捷径**——LLM 做指挥官（意图/风格/自然语言内心独白），
  引擎做执行者（合法性/精确计算），实现**观赏性对弈**（两个 LLM 棋手互相解释思考、
  风格碰撞：双马型 vs 双象型、进攻 vs 防守），观众实时看懂 AI 在想什么。
- Pair 23：生成完整备忘录下载（即 ES/YG 侧已见 memo 的最终版）。

## 二、可沉淀为机制资产的结论

| 资产 | 内容 | 主去向 |
| --- | --- | --- |
| **"系统一"可解释评估器** | 威胁/保护/牵制/控制边 + 王安全子图；静态 + 几步动态；图论指标（中心度/连通度/牵制度） | YG 引擎 toolbox 配置化评估器；Chess Engine AI 层；games_AI 原型 |
| **性格赋予三路线** | 传统=评估函数加风格项；DL=风格数据微调/风格损失/风格嵌入；RL=奖励塑形/约束优化/风格对抗 | 《棋类AI性格风格赋予技术备忘录》（已入 games_AI） |
| **双层闭环自调参** | 系统一权重可被遗传算法/回归/TD 或 GNN 端到端调优；与 AlphaZero 同哲学、更可解释 | 对接引擎 env MDP 接口（reward / 评估信号） |
| **教学式 AI** | 可调 level（深度限制+采样+ELO 分段）；故意留破绽；学习窗口/教学时刻 | Chess Games 本地 AI 升级；多邻国对标 |
| **符号 AI × RL 混合** | 硬约束 / 风格嵌入 / 分层架构 / 风格对抗 | CAG 多 agent 决策；复杂 AI 外置项目 |
| **LLM 指挥官 + 引擎执行者** | 一句话切风格、合法由引擎兜底、自然语言可解释 | 观赏性棋牌对弈 demo（暂缓立项） |
| **"求输 AI"（优雅的输）** | 不是无脑送子，而是"知道怎么赢但选次优" | 教学/陪练/整活场景 |

## 四、给 games_AI / ES 侧的建议动作

1. 与 YG 引擎设计对接：把"系统一"作为 **toolbox 内配置化评估器**候选原型
   （输入=棋子关系图特征，输出=可解释局面分），并预留 reward/评估双模式（Pair 12–13）。
2. 分层架构（符号层管风格 + RL 层管战术）值得在 ES 侧整理为**神经符号 RL 案例笔记**，
   与 ES 的"符号智能"研究线（SceneKit/RECS 决策）衔接。
3. 观赏性对弈（LLM 指挥官）暂缓独立立项；建议作为 games_AI 研究 demo 先行验证
   "LLM 一句话切风格 + 引擎兜底合法性"的最小闭环。
