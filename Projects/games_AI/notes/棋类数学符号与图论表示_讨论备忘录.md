## 二、棋盘、棋位、棋子、玩家的英文术语与数学符号

### 2.1 棋盘 (Chessboard)

* **英文**：Board
* **数学符号**：通常用大写字母表示，如 B。在更具体的上下文中，可以用 G\_{m×n} 表示一个 m 行 n 列的网格状棋盘。

### 2.2 棋位 (Square / Position / Cell)

* **英文**：Square 或 Position 或 Cell
* **数学符号**：通常用有序对 (i, j) 表示，其中 i 是行号，j 是列号。例如 (3, 4) 表示第 3 行第 4 列的棋位。也可以用单个字母如 s 或 p 表示一个棋位。

### 2.3 棋子 (Piece)

* **英文**：Piece
* **数学符号**：通常用小写字母表示，如 p。为了区分不同类型的棋子，可以用下标，如 p\_k 表示国王（King），p\_q 表示王后（Queen）等。也可以用集合 P 表示棋盘上所有棋子的集合。

### 2.4 玩家 (Player)

* **英文**：Player
* **数学符号**：通常用大写字母 P 表示。为了区分不同玩家，可以用下标，如 P₁ 和 P₂ 表示两个玩家。也可以用集合 Players = {P₁, P₂} 表示所有玩家的集合。

以上符号表示可以根据具体棋类游戏和数学建模的需要进行调整。

## 三、希腊字母表示方案

使用希腊字母来表示这些概念，可以赋予其更抽象或特定的数学含义。希腊字母通常用于表示特定类型的对象，如集合、函数或状态。

### 3.1 棋盘 (Board)

棋盘可以被看作是一个**空间**或一个**集合**。

| 建议符号 | 说明 |
| --- | --- |
| （花体 B） | “Board” 的首字母，用花体（Calligraphic）表示，是数学中表示特定集合或空间的常见做法，最直接且不易混淆 |
| Ω（Omega） | 希腊字母 Omega 常用来表示一个**全集**或**样本空间**，棋盘就是所有可能发生事件（棋子移动、占据等）的”宇宙”或空间 |

### 3.2 棋位 (Square / Position)

棋位是棋盘上的一个**点**或**坐标**。

| 建议符号 | 说明 |
| --- | --- |
| σ（sigma） | 小写 sigma 可以用来表示一个单一的元素或状态，代表棋盘上的一个特定位置 |
| ξ（xi） | 希腊字母 xi，常用来表示一个通用的变量或元素，形式上与 s 有些相似 |

### 3.3 棋子 (Piece)

棋子可以被看作是占据某个位置的**实体**，或者是一个**状态**。

| 建议符号 | 说明 |
| --- | --- |
| Π（Pi） | 大写 Pi 是 “Piece” 的首字母，形状独特，适合表示棋子的集合；小写 π 也可以用来表示单个棋子 |
| φ（phi）/ ψ（psi） | 纯希腊字母体系中，φ 或 ψ 常用来表示函数、状态或粒子，可抽象地代表一个棋子的状态 |

### 3.4 玩家 (Player)

玩家通常是一个**代理**或**参与者**，可以用一个索引或一个函数来表示。

| 建议符号 | 说明 |
| --- | --- |
| Φ（Phi） | 大写 Phi 常用来表示一个**策略函数**或**映射**，可以代表一个玩家，该玩家根据当前棋盘状态决定下一步行动。玩家集合可表示为 {Φ₁, Φ₂} |
| （花体 P） | “Player” 的首字母，用花体表示，是表示玩家集合的标准做法 |

### 3.5 希腊字母方案总结

| 概念 | 英文 | 推荐希腊字母表示 | 说明 |
| --- | --- | --- | --- |
| 棋盘 | Board |  | 最清晰、最标准的表示 |
| 棋位 | Square | σ | 表示棋盘上的一个具体位置 |
| 棋子 | Piece | π | 表示一个具体的棋子 |
| 玩家 | Player | Φ | 表示一个具有策略的玩家 |

### 3.6 数学描述示例

用希腊字母描述一个棋类游戏的状态：

* **棋盘** 是一个 8×8 的网格。
* 每个**棋位** σ ∈ 可以被一个**棋子** π 占据，或者为空。
* 有两个**玩家** Φ₁ 和 Φ₂，他们轮流选择一个棋子 π 并将其从一个位置 σ\_from 移动到另一个合法位置 σ\_to。

这种表示法比使用拉丁字母更具抽象性和数学美感，但需要在模型的开头进行明确定义，以确保清晰性。

## 四、图论术语规范

### 4.1 点 (Vertex)

| 项目 | 说明 |
| --- | --- |
| 规范术语 | **Vertex**（顶点） |
| 非规范术语 | Point / Dot（点） |
| 顶点集符号 | V（如 V = {v₁, v₂, …, v}） |
| 单个顶点符号 | v（i 为索引） |

**说明**：Vertex 是图论中的标准术语，指图中的基本单元。例如，无向图定义为 G = (V, E)，其中 V 为顶点集。Point / Dot 仅在非正式描述中使用，学术文献和数学定义中均采用 Vertex。

### 4.2 边 (Edge)

| 项目 | 说明 |
| --- | --- |
| 规范术语 | **Edge**（边） |
| 非规范术语 | Line（线） |
| 边集符号 | E（如 E = {e₁, e₂, …, e}） |
| 无向边符号 | (u, v) 或 uv（u, v ∈ V） |
| 有向边符号 | ⟨u, v⟩（从起点 u 指向终点 v） |

**说明**：Edge 是图论中唯一规范的术语，指连接顶点的线段或弧。Line 仅在非正式语境中出现，正式定义中必须使用 Edge。

### 4.3 术语对比总结

| 概念 | 规范术语 | 非规范术语 | 数学符号 |
| --- | --- | --- | --- |
| 图的基本单元 | Vertex | Point / Dot | V（顶点集） |
| 连接顶点的线 | Edge | Line | E（边集） |

### 4.4 扩展说明

* **有向图与无向图**：有向图的边称为**弧**（arc），但仍属于 edge 的子类，符号为 ⟨u, v⟩。
* **环**（loop）：连接同一顶点的边，如 (v, v)。
* **多重边**（multiple edges）：两顶点间多条边（在多重图中允许）。

## 五、棋盘作为网格图 (Grid Graph) 的表示

### 5.1 基本观点

棋盘本质是图（Graph），而国际象棋和围棋的棋盘属于特殊的**网格图（Grid Graph）**。对于这类结构，虽然二维数组坐标（如 (row, col)）能直观表示节点位置，但在图算法中需结合棋类规则设计更高效的表示方式。

### 5.2 国际象棋的图表示

国际象棋棋盘是 **8×8 的规则网格图**，其特点是：

* **节点连通性固定**：每个格子（节点）与相邻格子通过边连接，形成固定的网格拓扑。
* **边的权重隐含规则**：棋子的移动路径（边）受棋子类型约束，需在图中动态生成合法边。

**表示方案：**

1. **节点表示**：每个棋位用坐标 (r, c) 表示（r 为行，c 为列），共 64 个节点。
2. **边表示**：
   * **静态邻接表**：预存每个节点的相邻节点，适用于车、象等直线移动的棋子。
   * **动态边生成**：对马、王等特殊移动棋子，通过规则函数实时计算合法目标节点。
3. **图结构选择**：
   * **邻接表（Adjacency List）**：空间复杂度 O(V)，适合稀疏连接的网格图。
   * **状态附加信息**：节点属性记录棋子类型和所属玩家；边属性可标记移动类型（如”吃子”“王车易位”）。

**示例 — 马的移动图：**

def get\_knight\_moves(r, c):
 moves = [(r+2,c+1), (r+2,c-1), (r-2,c+1), (r-2,c-1),
 (r+1,c+2), (r+1,c-2), (r-1,c+2), (r-1,c-2)]
 return [(nr, nc) for nr, nc in moves if 0<=nr<8 and 0<=nc<8]

### 5.3 围棋的图表示

围棋棋盘是 **19×19 的网格图**，其特殊性在于：

* **动态连通性**：棋子落子后形成”气”（自由度），连通块的合并与消除需实时更新图结构。
* **边的语义复杂**：相邻同色棋子形成连通块，提子操作会删除节点并重建边。

**表示方案：**

1. **节点表示**：棋位坐标 (r, c) 表示交叉点，节点状态记录为空、黑子或白子。
2. **边表示**：
   * **四邻域连接**：每个节点默认与上下左右四个相邻节点相连（边界除外）。
   * **连通块（Group）抽象**：将相邻同色棋子聚合为超节点，简化”气”的计算。
3. **图结构选择**：
   * **邻接矩阵 + 并查集（Union-Find）**：邻接矩阵快速查询相邻关系 O(1)；并查集高效维护连通块，支持合并与拆分操作。
   * **属性图（Attributed Graph）**：节点属性为棋子颜色和所属连通块ID；边属性标记是否为”边界边”。

**示例 — 连通块与气的计算：**

class GoGraph:
 def \_\_init\_\_(self):
 self.board = {} # (r,c) -> color
 self.groups = {} # group\_id -> set of (r,c)

 def add\_stone(self, r, c, color):
 self.board[(r,c)] = color
 new\_group = {(r,c)}
 for nr, nc in [(r+1,c), (r-1,c), (r,c+1), (r,c-1)]:
 if (nr,nc) in self.board and self.board[(nr,nc)] == color:
 merged = new\_group | self.groups.pop(get\_group\_id(nr,nc))
 new\_group = merged
 group\_id = generate\_id()
 self.groups[group\_id] = new\_group

### 5.4 两种棋类的图表示对比

| 特性 | 国际象棋 | 围棋 |
| --- | --- | --- |
| 节点类型 | 固定 64 个棋位 | 固定 361 个交叉点 |
| 边生成方式 | 静态邻接表 + 动态规则函数 | 静态四邻域 + 动态连通块合并 |
| 核心操作 | 路径搜索（如 A\* 算法） | 连通性维护（并查集） |
| 空间复杂度 | O(V)（邻接表） | O(V)（邻接矩阵 + 并查集） |
| 适用算法 | 最短路径、博弈树剪枝 | 连通块分析、围地面积计算 |

### 5.5 优化建议

1. **稀疏图优化**：国际象棋中大部分棋子移动范围有限，邻接表比邻接矩阵更节省空间。
2. **动态图更新**：围棋需频繁更新连通块，使用并查集可将合并操作优化至接近 O(1)。
3. **规则嵌入**：将棋类规则（如国际象棋的”吃过路兵”、围棋的”打劫”）编码为图操作的约束条件，避免生成非法状态。

### 6.5 符号选择建议

* **优先使用 P 或** ：简洁且符合集合表示惯例。
* **避免歧义**：若 p 已用于其他含义（如概率），可改用 C（chess pieces）或 Π（希腊字母）。
