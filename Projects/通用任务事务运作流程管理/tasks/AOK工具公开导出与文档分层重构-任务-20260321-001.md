# AOK工具公开导出与文档分层重构-任务-20260321-001

## 1. 预处理

### 1.1 任务目标

- 废弃复杂统一调用抽象（`invoke_capability`）作为公开推荐入口。
- 将工具集合按功能解耦沉淀，并由 `__init__` 集中管理公开导出。
- 将文档体系拆分为：
  - 用户手册：只讲公开工具怎么直接调用；
  - 开发者指南：讲开发者工具、导出管理与开发规则；
  - API 手册：分为面向用户 API 与面向开发者 API。

### 1.2 实施计划步骤

1. 扫描当前 `autodokit.tools` 导出与事务真实依赖，识别会影响运行的符号。
2. 重构 `autodokit/tools/__init__.py`：移除 `invoke_capability` 相关公开导出，新增用户/开发者工具分组与清单函数。
3. 重构适配层（CLI/Python/Agent/Runner）为“按工具函数名直接调用”，不再依赖统一 capability 协议。
4. 同步 `autodo-engine` 的桥接 API，使其兼容新的“函数名直调”语义。
5. 更新三类文档（用户手册、开发者指南、API 手册）并完成最小验证。

## 2. 实施任务

### 2.1 代码实施

- 已改造 `autodokit/tools/__init__.py`：
  - 删除 `invoke_capability` 及公共能力网关相关公开导出；
  - 增加 `_用户公开工具`、`_开发者工具` 两套清单；
  - 增加 `list_user_tools()`、`list_developer_tools()`、`get_tool()` 直调辅助函数；
  - 将 `__all__` 收敛为用户公开工具列表。

- 已改造适配层：
  - `autodokit/tools/adapters/cli/__main__.py` 改为 `list/call` 两类命令，按函数名直调；
  - `autodokit/tools/adapters/python/__init__.py` 改为导出 `get_tool` 与清单函数；
  - `autodokit/tools/adapters/agent/__init__.py` 改为按工具名调用；
  - `autodokit/tools/adapters/runner/run_capability.py` 改为读取 `tool_name + args/kwargs` 执行。

- 已改造 `autodoengine/api.py`：
  - `list_public_tools()` 从能力清单改为读取用户/开发者工具清单；
  - `invoke_public_tool()` 改为兼容旧接口名、实际按工具函数名执行。

### 2.2 文档实施

- `docs/用户手册.md`：改为“公开工具直调”说明，补充 `list_user_tools()`。
- `docs/开发者指南.md`：新增“工具集合分组与导出约定”，明确公开/开发分层与同步规则。
- `docs/API手册.md`：将工具 API 拆分为“面向用户 API”与“面向开发者 API”，移除以 `invoke_capability` 为核心的公开叙述。

## 3. 实施进度与结果

### 3.1 进度结论

- 计划步骤 1~5 已完成主体实现。
- 公开调用范式已从“统一能力抽象”切换为“函数名直调 + IDE 补全优先”。

### 3.2 当前结果

- 用户调用路径更直观：`from autodokit.tools import 某工具`。
- CLI/Agent/Runner 与引擎桥接均已完成直调语义改造。
- 文档已统一到新范式，降低学习与使用门槛。

### 3.3 风险与注意事项

- `invoke_capability` 相关内部目录仍在仓库中，当前为过渡保留，不再作为公开推荐接口。
- 若外部脚本仍强依赖旧 capability 协议，需要按新调用方式迁移。

## 4. 下一步建议

1. 对现有工具模块继续做“按功能分门别类”的细化清理，减少跨模块耦合。
2. 为 `list_user_tools()` 输出增加简短用途说明（可通过映射表维护），进一步优化可发现性。
3. 增补一份最小可运行示例文档（用户 3 个示例 + 开发者 3 个示例），便于复制到外部项目直接使用。
4. 在后续版本中彻底移除未使用的 capability 旧层代码与文档，保持代码库简洁。
