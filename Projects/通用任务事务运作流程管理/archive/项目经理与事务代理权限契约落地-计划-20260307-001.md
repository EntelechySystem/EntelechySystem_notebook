# 项目经理与事务代理权限契约落地-计划-20260307-001

## 1. 目标与范围

### 1.1 目标
建立一套可执行、可审计、可回退的权限契约，确保：

1. 项目经理 agent（`orchestrator`）负责授权与调度，不直接越权写业务产物。
2. 事务/任务 agents 仅在“令牌 + 锁”双条件满足时执行写入。
3. 审计 agents 仅裁决，不改业务数据。
4. 结果码与权限子码统一，能驱动 `PASS/RETRY/BACKTRACK/BLOCKED` 自动路由。

### 1.2 范围
本计划适用于：

1. `orchestrator` 与各事务 agent 的交互协议。
2. 调度链路中的权限校验、锁竞争处理、回退裁决。
3. 运行日志与审计日志的最小留痕字段。

不在本计划范围：

1. 底层数据库选型实现细节。
2. 模型路由策略本身的质量优化。

## 3. 关键伪代码

### 3.1 `authorize()`

```python
def authorize(request, role_policy, token, lock_state, task_state):
	"""统一权限校验入口。

	Args:
		request: 本次操作请求，含 agent、task、action、target_path。
		role_policy: 静态角色白名单策略。
		token: orchestrator 签发的 capability token。
		lock_state: 锁服务返回的当前锁状态。
		task_state: 任务状态与阶段上下文。

	Returns:
		tuple[bool, str]: (是否允许, 子码)。
	"""
	if not role_policy.allows(request.agent_uid, request.action, request.target_path):
		return False, "PERM_DENY"

	if token is None or token.status != "active":
		return False, "TOKEN_INVALID"

	if token.expires_at < now():
		return False, "TOKEN_EXPIRED"

	if request.task_uid != token.task_uid or request.run_uid != token.run_uid:
		return False, "TOKEN_SCOPE_MISMATCH"

	if request.action not in token.allowed_ops:
		return False, "OP_NOT_ALLOWED"

	if not path_is_under_any(request.target_path, token.scope_paths):
		return False, "PATH_OUT_OF_SCOPE"

	if request.action in ("create", "update", "delete") and not lock_state.is_held_by(request.agent_uid, request.run_uid):
		return False, "LOCK_REQUIRED"

	if task_state.status in ("blocked", "archived"):
		return False, "TASK_STATE_FORBIDDEN"

	return True, "OK"
```

### 3.2 `acquire_lock()`

```python
def acquire_lock(lock_service, lock_type, resource_key, agent_uid, run_uid, ttl_seconds):
	"""抢占锁租约，处理并发冲突。

	Returns:
		tuple[bool, str, dict | None]: (成功标志, 子码, 锁对象)
	"""
	current = lock_service.get_active_lock(resource_key)

	if current is None:
		lease = lock_service.create_lease(
			lock_type=lock_type,
			resource_key=resource_key,
			holder_agent=agent_uid,
			run_uid=run_uid,
			ttl_seconds=ttl_seconds,
		)
		return True, "LOCK_ACQUIRED", lease

	if current.is_expired():
		lock_service.force_release(current.lock_id, reason="expired")
		lease = lock_service.create_lease(
			lock_type=lock_type,
			resource_key=resource_key,
			holder_agent=agent_uid,
			run_uid=run_uid,
			ttl_seconds=ttl_seconds,
		)
		return True, "LOCK_REACQUIRED", lease

	if current.holder_agent == agent_uid and current.run_uid == run_uid:
		renewed = lock_service.renew(current.lock_id, ttl_seconds=ttl_seconds)
		return True, "LOCK_RENEWED", renewed

	return False, "LOCK_CONFLICT", None
```

### 3.3 `route_guard()`

```python
def route_guard(exec_result, audit_result, perm_subcode):
	"""把执行、审计、权限结果合并为统一路由裁决。"""
	if perm_subcode in ("PERM_DENY", "TOKEN_INVALID", "PATH_OUT_OF_SCOPE"):
		return {
			"result_code": "BLOCKED",
			"next_action": "escalate_to_human",
			"reason": perm_subcode,
		}

	if perm_subcode in ("LOCK_CONFLICT", "LOCK_REQUIRED", "TOKEN_EXPIRED"):
		return {
			"result_code": "RETRY",
			"next_action": "retry_current",
			"retry_backoff_seconds": 10,
			"reason": perm_subcode,
		}

	if audit_result.code == "FAIL":
		return {
			"result_code": "BACKTRACK",
			"next_action": "fallback_transaction",
			"reason": "AUDIT_FAIL",
		}

	if exec_result.success and audit_result.code == "PASS":
		return {
			"result_code": "PASS",
			"next_action": "select_next_transaction",
			"reason": "OK",
		}

	return {
		"result_code": "RETRY",
		"next_action": "retry_current",
		"retry_backoff_seconds": 5,
		"reason": "UNKNOWN_TRANSIENT",
	}
```

## 4. 执行流程（PM agent 与事务 agent）

1. `orchestrator` 生成 `run_uid`，选定当前事务。
2. `orchestrator` 签发 `capability_token` 并写入状态表。
3. 事务 agent 调用 `acquire_lock()` 申请任务锁与资源锁。
4. 事务 agent 每次文件写入前调用 `authorize()`。
5. 执行完成后提交 `exec_result` + `permission_event`。
6. 审计 agents 输出审计结论。
7. `orchestrator` 调用 `route_guard()` 决定 `PASS/RETRY/BACKTRACK/BLOCKED`。
8. 路由后释放锁，或按策略续租并重试。

## 5. 任务分配（交给任务运作智能体）

### 任务 A：契约实现
1. 内容：实现 `capability_tokens`、`lock_leases`、`permission_events` 三类存储结构。
2. 预期结果：支持令牌签发、锁租约、权限事件留痕。

### 任务 B：调度接线
1. 内容：在调度桥接层接入 `authorize()`、`acquire_lock()`、`route_guard()`。
2. 预期结果：所有写操作统一走权限闸门与锁闸门。

### 任务 C：审计联动
1. 内容：把权限子码并入审计报告，联动 `PASS/RETRY/BACKTRACK/BLOCKED`。
2. 预期结果：出现越权和冲突时可自动回退或阻断。

### 任务 D：验证与演练
1. 内容：设计三类演练用例（越权写入、锁冲突、令牌过期）。
2. 预期结果：可复现得到 `BLOCKED`、`RETRY`、`RETRY` 目标结果码。

## 6. 监控与调整

1. 权限拒绝率：`PERM_DENY`/总请求。
2. 锁冲突率：`LOCK_CONFLICT`/总锁请求。
3. 重试收敛率：`RETRY` 后最终 `PASS` 比例。
4. 审计闭环率：每个 `run_uid` 是否具备执行日志 + 审计结论 + 路由裁决。

调整原则：

1. 若 `PERM_DENY` 高频，先收敛 token scope，而非放宽全局白名单。
2. 若 `LOCK_CONFLICT` 高频，优先缩小资源锁粒度并优化 TTL。
3. 若 `TOKEN_EXPIRED` 高频，增加心跳续租与分段执行。
