# OC代理与ARK技能对齐开发汇报-报告-20260307-001

## 1. 背景

本汇报基于 `plan-学术事务调度与三库开发实施总计划-20260306-001.md`，对当前 `OpenCode`（OC）代理与技能体系、`academicresearch_kit`（ARK）已实现能力，以及两者之间的桥接情况进行盘点、补全与开发汇报。

本轮目标：

1. 盘点 OC Agents 与学术科研流程设计方案的对齐情况。
2. 盘点 OC Skills、OC scripts、ARK skills、ARK tools 的对齐情况。
3. 把当前已有实现但缺失桥接的一侧补到另一侧。
4. 输出当前根据总计划已完成的开发进度。

## 2. 当前总计划开发状态

对照 `plan-学术事务调度与三库开发实施总计划-20260306-001.md`，当前状态如下。

### 2.1 已有基础实现

1. `阶段 0 初始化`：已基本落位。
- 仓库内已存在 `database/tasks`、`database/references`、`database/knowledge`、`config/scheduler`。
- `sandbox/opencode_skill_bootstrap_demo/` 中已有模板化产物。

2. `阶段 1 调度闭环 MVP`：核心代码已存在。
- 已有 `academicresearch_kit/scheduler_core/`。
- 已有 `SchedulerService`、`DispatchExecutor`、`DispatchEventLogger` 等模块。
- 但在本轮之前，OC 侧缺少正式的 `scheduler-dispatch` skill 外壳与脚本桥接。

3. `阶段 2 事务/任务管理完善`：核心代码已存在。
- 已有 `academicresearch_kit/tasking_db/`。
- 已有 `ProjectBootstrapper`、`IntegrityChecker`、`ReplayEngine`。
- 但在本轮之前，OC 侧缺少 `taskdb-bootstrap`、`taskdb-validate`、`taskdb-replay` skill 对接。

4. `阶段 5 检索治理接入`：最小治理引擎已存在。
- 已有 `academicresearch_kit/retrieval_governance/engine.py`。
- 已能返回 `bundle` 与 `next_node`。
- 但在本轮之前，OC 侧缺少统一的 `retrieval-governance` skill 外壳。

### 2.2 当前仍未完成的部分

1. `阶段 3 文献管理落地`：仍缺条目 CRUD、清单更新器、附件索引与向量化落地。
2. `阶段 4 知识管理落地`：仍缺知识笔记入库、证据映射维护与任务驱动查询。
3. 高层研究能力仍多为 markdown 规则，尚未全部脚本化：
- `cn-local-library-manager`
- `cn-web-acquisition`
- `econometrics-runtime-setup`
- `did-rdd-pipeline`
- `empirical-four-pack`
- `rag-evidence-synthesis`
- `paper-draft`
- `revision-response`
- `variable-operationalization`
- `whitelist-governance-check`

### 3.1 对齐结论

1. 现有 OC Agents 基本覆盖了科研主链上的业务角色。
2. 本轮之前缺的不是“研究角色”，而是“状态管理角色”。
3. 因此本轮新增了：
- `task-state-manager`
- `transaction-state-manager`
4. 同时把 `orchestrator` 与多个垂直代理改为显式对齐 `L0-L4` 多层架构与 `database/logs` 留痕。

### 4.1 对齐结论

1. 本轮之前，ARK 已有 4 个可执行 skill，但 OC 侧并未完全补齐对应脚本。
2. 本轮新增 5 组“ARK 已实现能力 -> OC Skill 外壳”的桥接：
- `retrieval-governance`
- `scheduler-dispatch`
- `taskdb-bootstrap`
- `taskdb-validate`
- `taskdb-replay`
3. 同时把 ARK 侧的可执行 skill 数量从 4 个扩展到 9 个。
4. 当前仍未脚本化的技能，多数属于高层研究业务逻辑，不是桥接缺失，而是底层实现尚未完成。

## 7. 风险与未完成项

1. 本轮只做开发，不做统一调试。
2. `model-routing-dispatch`、`scheduler-dispatch`、`taskdb-*` 还未做端到端烟雾验证。
3. 文献管理、知识管理、计量执行、RAG 与写作类高层技能仍未脚本化。
4. `task-state-manager` 与 `transaction-state-manager` 当前先补为代理契约，还未与真实 CSV 写回动作绑定。

## 8. 结论

本轮完成的是“桥接层补齐 + 治理层对齐 + 文档纠偏”。

可确认的阶段性成果：

1. OC 与 ARK 之间已形成 9 条正式 skill 调用链。
2. 学术科研流程中的 `L0-L4` 多层角色已经在 OC Agents 侧显式落位。
3. 根据总计划，调度 MVP、taskdb MVP、检索治理 MVP 已从“代码存在但桥接零散”推进到“代码、代理、脚本、文档四位一体”。
4. 下一步不应继续盲目扩技能数量，而应先统一调试、验证、回放，再扩展文献管理与知识管理等高层能力。
