# CNKI最小闭环真实执行-任务-20260308-001

## 1. 任务背景

本任务对应 `plan-CNKI检索能力整合落地计划-20260308-001.md` 的第一步执行目标：先把 `cnki-search`、`cnki-paper-detail`、`cnki-export` 做成第一条真实可跑的最小闭环。

这里的“真实可跑”定义为：

1. 不再只返回协议占位。
2. 可以真实启动浏览器执行站点访问。
3. 在遇到 CNKI 安全验证、登录等情况时，返回结构化阻断状态，而不是 Python 异常。

## 2. 可行性分析

当前仓库已具备 `playwright` 依赖与项目 `.venv`，因此可以用 Playwright 作为 OpenCode 侧的真实页面执行基础。

风险点主要有两个：

1. CNKI 会直接跳安全验证页，导致页面 selector 失效。
2. 当前机器没有 Playwright 的 `chrome` channel，但存在 Edge，因此需要浏览器启动回退链。

## 3. 计划步骤

1. 新增 CNKI Playwright 真实执行器。
2. 为 `cnki-search`、`cnki-paper-detail`、`cnki-export` 增加 `execute` 模式。
3. 验证真实执行时，安全验证会被转成 `captcha_required`。
4. 为导出链增加本地产物落盘与后续桥接基础。

## 4. 实施记录

### 4.1 新增真实执行层

已新增：

1. `academicresearch_kit/domains/cnki/runtime.py`
2. `academicresearch_kit/domains/cnki/artifacts.py`

其中：

1. `runtime.py` 提供 Playwright 浏览器启动、页面导航、检索、详情、导出等真实执行能力。
2. `artifacts.py` 提供 RIS、GB/T、本地 JSON、manifest 及 Zotero Connector 推送等工具。

已更新：

4. `.opencode/skills/cnki-export/scripts/run_cnki_export.py`

这些入口现在同时支持：

1. 默认返回计划协议。
2. 加 `--execute` 后走真实浏览器执行。

### 4.3 烟雾验证结果

已验证：

1. `.venv` 中 `playwright` 与 `academicresearch_kit` 可正常导入。
2. 真实执行器可正常拉起 Edge。
3. 执行 `cnki-search` 时，CNKI 当前会跳到安全验证页。
4. 当前实现已把这一情况转成：`status=BLOCKED`、`reason=captcha_required` 的结构化结果。
