# OC代理与ARK对齐补全开发-任务-20260307-001

## 1. 任务背景

用户要求：

1. 检查当前 OC Agents 与学术科研流程设计方案的对齐情况。
2. 检查当前 OC Skills 与 ARK Skills 脚本、工具之间的对齐情况。
3. 把对方没有的补充到对方那边。
4. 生成汇报到 `.github/docs/report/`。
5. 生成新的 plan 到 `.github/docs/plan/`。
6. 新建 task 并着手开发。
7. 本轮只开发，不统一调试。
8. 开发完成后同步更新 `academicresearch_kit/docs`。

## 2. 可行性分析

### 2.1 可直接实施的部分

1. OC Agents 对齐分析：仓库已有 `.opencode/agents/`，可以直接盘点与改造。
2. OC Skills 与 ARK Skills/工具对齐分析：仓库已有 `.opencode/skills/`、`academicresearch_kit/skills/`、`academicresearch_kit/tools/`，可以直接建立映射表。
3. 缺失桥接补齐：对于 ARK 已有实现但 OC 侧缺失 skill 外壳或脚本的部分，可以直接开发。
4. 文档同步：`academicresearch_kit/docs/` 当前文档与真实实现有偏差，适合本轮一起纠偏。

### 2.2 暂不直接实施的部分

1. 文献管理、知识管理、计量分析、RAG、写作类高层技能的完整脚本化。
2. 统一调试、冒烟测试、端到端联调。

原因：

1. 用户明确要求“只开发不调试”。
2. 上述高层能力的底层实现仍未齐备，现阶段更适合先补桥接层与治理层。

## 3. 实施计划

1. 盘点现有 OC Agents、OC Skills、ARK Skills、ARK Tools。
2. 形成对齐矩阵，找出“已有实现但缺少桥接”的缺口。
3. ARK 侧补 skill 包装模块。
4. OC 侧补 skill 目录说明与脚本桥接。
5. OC Agents 增补状态管理角色，并将协同矩阵对齐到 `L0-L4`。
6. 同步更新 `academicresearch_kit/docs`。
7. 输出 report、plan、task 文档。

## 5. 当前结果

### 5.1 已完成结果

1. OC 与 ARK 之间已形成 9 条正式 skill 调用链。
2. OC Agents 已补齐科研流程中的任务状态层与事务状态层角色。
3. `academicresearch_kit/docs` 已从旧说明纠偏为当前真实结构。
4. 已输出本轮汇报与下一轮联调计划。
5. 文献主链已从“检索后直接进 RAG”调整为“导入 -> 预筛选 -> 阅读 -> 证据综合”的四段式结构。
6. 预筛选职责已从文献资产管理中剥离，并明确归入知识管理前置环节。

### 5.2 未完成结果

1. 尚未统一调试上述脚本与技能链路。
2. `task-state-manager`、`transaction-state-manager` 仍是代理契约，尚未落成显式 Python 写回技能。
3. 高层研究技能仍有大量未脚本化项。
4. `local-reference-ingestion` 当前已能解析本地 `bib` / `rdf` 并写入数据库模板，但尚未补齐更复杂的附件智能匹配与全文提取链。
5. `knowledge-prescreen` 与 `literature-reading` 当前属于最小可执行骨架，后续还需接入真实知识库、文献矩阵和精读输出文件。

### 5.3 本轮验证情况

1. 新增与更新的 Python 文件已执行编辑器错误检查，当前未发现语法或静态分析错误。
2. 顶层导出链路已进行最小导入验证，导入过程已进入 `academicresearch_kit.local_reference_ingestion` 新模块。
3. 当前运行环境缺少 `bibtexparser` 依赖，导致最小导入验证在运行期被环境阻断；结合 `pyproject.toml` 已声明该依赖，可判断此处属于环境未安装依赖，而非本轮代码漏配。
