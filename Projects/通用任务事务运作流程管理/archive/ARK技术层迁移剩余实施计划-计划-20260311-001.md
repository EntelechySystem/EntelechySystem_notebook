# ARK技术层迁移剩余实施计划-计划-20260311-001

## 1. 背景与当前状态

基于蓝图 `plan-ARK技术层迁移AOK实施蓝图V1-20260310-001.md` 与当前仓库状态对照：

1. S1 已完成：`academicresearch_kit/scheduler_core/`、`academicresearch_kit/tasking_db/` 已删除。
2. S2 已完成：`academicresearch_kit/tools/project_runtime.py`、`academicresearch_kit/tools/flow_trace.py` 已删除并归一到 AOK。
3. S3 已完成：ARK 旧调度实现目录已删除，AOK `autodokit/scheduling/*` 与运行链接入已落地。
4. S4 已完成：AOK `autodokit/taskdb/*` 已建立，ARK 旧 `platform/taskdb` 已删除并改为门面代理。
5. 当前主要剩余：S5（领域引擎事务化迁移）与最终 DoD 验收闭环。

## 2. 本计划目标（剩余部分）

1. 完成 S5：将 ARK 领域引擎按事务颗粒迁入 AOK affairs，ARK skills 切换调用链。
2. 迁移完成即删除 ARK 对应 domains 实现，保持“单一技术内核”。
3. 完成三类统一验收：结果一致性、回放一致性、日志字段一致性。
4. 完成文档收口：删除“ARK 自有技术内核”描述，统一为“ARK 语义编排 + AOK 技术内核”。

## 3. 剩余范围与对象

### 3.1 待迁移 domains（ARK -> AOK affairs）

1. `academicresearch_kit/domains/local_reference_ingestion/engine.py`
2. `academicresearch_kit/domains/knowledge_prescreen/engine.py`
3. `academicresearch_kit/domains/literature_reading/engine.py`
4. `academicresearch_kit/domains/retrieval_governance/engine.py`
5. `academicresearch_kit/domains/cnki/*`

### 3.2 待切换调用面（ARK）

1. `academicresearch_kit/skills/local_reference_ingestion.py`
2. `academicresearch_kit/skills/knowledge_prescreen.py`
3. `academicresearch_kit/skills/literature_reading.py`
4. `academicresearch_kit/skills/cnki_bridge.py`
5. `academicresearch_kit/api/retrieval.py`
6. `academicresearch_kit/__init__.py`（对外导出收口）

## 4. 分阶段实施方案

## P1：先迁三件套（低耦合优先）

### P1.1 迁移内容

1. 在 AOK 新增 affairs：
- `reference.local_ingestion`
- `knowledge.prescreen`
- `literature.reading`

2. 在 ARK skills 切换调用来源（由 domains 改为 AOK affairs/API）。

3. 删除 ARK 对应 domains：
- `domains/local_reference_ingestion/`
- `domains/knowledge_prescreen/`
- `domains/literature_reading/`

### P1.2 验收标准

1. 同输入下输出结构字段一致（结果一致性）。
2. 执行日志可在 AOK taskdb 回放（回放一致性）。
3. 日志字段包含必填 schema（日志字段一致性）。

## P2：迁移 retrieval_governance（中耦合）

### P2.1 迁移内容

1. 在 AOK 新增 affairs：
- `retrieval.governance`
- `retrieval.route`

2. ARK `api/retrieval.py` 改为 AOK 门面代理。

3. 删除 ARK `domains/retrieval_governance/`。

### P2.2 验收标准

1. `default_retrieval_handler` 语义输出一致。
2. 被调度链路调用时 `result_code`、`next_node` 行为一致。
3. 调度扩展字段 `selection/guard_decision/receipt` 完整。

## P3：迁移 CNKI 子域（高耦合，独立批次）

### P3.1 迁移内容

1. 在 AOK 按功能拆分 affairs：
- `cnki.search`
- `cnki.paper_detail`
- `cnki.journal_index`
- `cnki.journal_toc`
- `cnki.export`

2. ARK `skills/cnki_bridge.py` 切换到 AOK affairs。

3. 删除 ARK `domains/cnki/`。

### P3.2 验收标准

1. 查询、详情、目录、导出产物字段一致。
2. 导出 artifacts 与 manifest 字段一致。
3. 人工接管异常路径（manual intervention）行为一致。

## P4：最终收口（DoD）

### P4.1 代码与导出收口

1. 清理 ARK `__init__.py` 中对已删除 domains 的导出。
2. 确认 ARK 不再含技术内核重复实现。

### P4.2 文档收口

1. 更新 `academicresearch_kit/docs/API手册.md`。
2. 删除/改写所有“ARK 自有调度内核、自有 taskdb 内核”描述。

### P4.3 全量验收

1. 结果一致性：关键技能链路抽样回归通过。
2. 回放一致性：同 run 数据回放状态轨迹一致。
3. 日志字段一致性：必填字段与调度扩展字段完整。

## 5. 执行顺序与里程碑

1. 里程碑 M1：完成 P1 三件套迁移与删除。
2. 里程碑 M2：完成 P2 retrieval_governance 迁移与删除。
3. 里程碑 M3：完成 P3 CNKI 迁移与删除。
4. 里程碑 M4：完成 P4 文档与 DoD 验收。

## 6. 风险与控制

1. 风险：skills 调用切换引起契约不一致。
- 控制：每个子域先做“输入/输出字段映射表”，再改代码。

2. 风险：删除 domains 后出现隐藏导入残留。
- 控制：每次删除后执行全仓 `grep_search` + `get_errors`。

3. 风险：CNKI 子域耦合高，回归范围大。
- 控制：CNKI 独立批次，完成后立即闭环验收，不与其他子域混改。

## 7. 完成定义（本剩余计划）

满足以下条件即视为剩余计划完成：

1. S5 全部子域迁移完成并删除 ARK 对应 domains。
2. ARK 仅保留语义编排层，不含技术引擎重复实现。
3. 三类一致性验收全部通过并留存任务文档记录。
