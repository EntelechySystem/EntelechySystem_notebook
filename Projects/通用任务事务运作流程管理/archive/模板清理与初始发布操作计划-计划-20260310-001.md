# 模板清理与初始发布操作计划-计划-20260310-001

## 1. 计划目标

基于当前仓库实际状态，完成“模板化清理”，使仓库可作为学术科研工作流系统的初始文件夹模板。

目标结果：

- 保留结构骨架与核心能力
- 清除环境、日志、回归产物、个人数据痕迹
- 形成可复用的模板发布流程

- `.opencode/` 规则、技能、代理、工作流结构完整

## 4. 操作计划（分阶段执行）

### 阶段 A：快照与风险控制

1. 创建模板清理分支。
2. 导出当前目录树快照与 `git status`。
3. 标记含真实数据目录（尤其 `references/origin/user_uploads/`）。

验收：可回滚点建立完成。

### 阶段 B：运行产物清理

1. 删除日志、回归、沙盒、node_modules。
2. 删除 taskdb 运行态 jsonl。
3. 保留目录骨架（必要时写入 `.gitkeep`）。

验收：`logs/run`、`demos/*_drytest*`、`sandbox` 清空。

### 阶段 C：环境与工具痕迹清理

1. 删除 `.venv`、`.idea`、`.sync.ffs_db`。
2. 视策略处理 `.vscode`。
3. 视策略处理 `egg-info` 和 `uv.lock`。

验收：无本机绑定环境痕迹。

### 阶段 D：模板自检

1. 执行最小 dry-run。
2. 初始化并校验 taskdb。
3. 运行检索和调度最小链路。

验收：模板克隆后最小链路可运行。

### 阶段 E：发布与归档

1. 生成模板发布报告。
2. 打标签 `template-vYYYYMMDD`。
3. 更新 `README.md` 的“模板使用”章节。

验收：可公开复用的初始模板完成。

## 6. 风险与回滚

- 风险 1：误删模板骨架目录。
处置：先建快照分支，必要时 `git restore` 单目录恢复。
- 风险 2：误删需要保留的示例 workflow。
处置：保留 `demos/workflows/`，只删带时间戳回归产物目录。
- 风险 3：清理后首次运行失败。
处置：按手册重新执行环境初始化与最小 dry-run。
