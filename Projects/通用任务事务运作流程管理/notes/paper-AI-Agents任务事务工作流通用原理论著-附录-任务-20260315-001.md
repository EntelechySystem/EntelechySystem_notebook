## 附录 A. v4 最小实践框架

v4 的最小实践目标不是完成学习型工作流，而是完成以下三件事：

1. 把控制面统一切换到 MDP 术语体系。
2. 把 PA、TA、NA、AA 都定义为 Agent 角色。
3. 把最终裁决统一收口到决策部门。

因此，v4 的实践顺序应为：

1. 保留 v3 的结果码协议与任务状态机。
2. 重写文档与接口术语，使其全面转为状态、观测、动作、转移、决策者的口径。
3. 为 PA、TA、NA、AA 定义统一的结构化输入输出。
4. 把决策记录改写为决策部门口径。
5. 为后续 v5 的学习系统预留稳定数据集格式。

## 附录 B. v4 最小 MDP 术语映射

### B.1 状态

状态指当前任务步上的结构化世界快照，包括：

1. 任务状态
2. 当前节点
3. 当前事务回执
4. 任务预算与历史摘要
5. 父子任务关系
6. 人工闸门与阻断信息

### B.2 观测

观测指某一 Agent 或决策部门在当前时刻接收到的信息摘要，包括：

1. 任务摘要
2. 节点摘要
3. 回执摘要
4. 候选动作摘要
5. 证据摘要

### B.3 动作

v4 沿用 v3 动作集：

1. `continue`
2. `retry`
3. `backtrack`
4. `suspend`
5. `split`
6. `human_gate`
7. `complete`
8. `fail`
9. `cancel`

### B.4 转移

转移仍由任务状态机定义。也就是说，动作可以用 MDP 语言表述，但动作执行后的合法状态变化仍受 v3 状态机约束。

## 附录 C. Agent 角色最小清单

### C.1 PA

- 定位：项目级 Agent
- 当前地位：决策部门默认成员
- 当前职责：高层治理裁决

### C.2 TA

- 定位：任务级 Agent
- 当前地位：定义接口，默认不承担最终裁决
- 当前职责：任务级状态组织、候选动作整理、任务摘要提供

### C.3 NA

- 定位：节点级 Agent
- 当前地位：定义接口，默认不承担最终裁决
- 当前职责：节点级语义、风险、候选路径解释

### C.4 AA

- 定位：事务级 Agent
- 当前地位：定义接口，默认不承担最终裁决
- 当前职责：事务执行结果整理、回执翻译、失败解释

### C.5 人类专家

- 定位：外部高权限治理主体
- 当前地位：决策部门默认成员
- 当前职责：高风险动作审批与最终确认

## 附录 D. 决策部门最小契约

### D.1 输入包

决策部门最小输入字段建议为：

1. `decision_uid`
2. `task_uid`
3. `task_summary`
4. `node_summary`
5. `receipt`
6. `candidate_actions`
7. `evidence`
8. `agent_recommendations`

### D.2 输出包

决策部门最小输出字段建议为：

1. `selected_action`
2. `reason_code`
3. `reason_text`
4. `next_node_uid`
5. `split_children`
6. `human_gate_request`
7. `decision_actor`

## 附录 E. v4 与 v3 的连续性

v4 必须保留的 v3 资产包括：

1. 结果码协议
2. 任务状态机
3. 结构化决策记录
4. 四类核心数据库
5. 单步闭环执行主干

## 附录 F. v4 与 v5 的接口准备

v5 若要引入多智能体强化学习，v4 至少已提前准备以下接口：

1. 统一 Agent 命名体系
2. 统一状态/观测/动作语言
3. 统一决策部门输出格式
4. 统一证据与决策记录格式
5. 统一角色扩展入口

## 附录 G. 附录结论

v4 的最小实践框架并不要求系统立刻学习或自治，而是要求系统先把未来学习所依赖的全部接口语言稳定下来。只有这样，后续从决策部门人工裁决过渡到多智能体强化学习时，系统才不会在协议层面发生断裂。
