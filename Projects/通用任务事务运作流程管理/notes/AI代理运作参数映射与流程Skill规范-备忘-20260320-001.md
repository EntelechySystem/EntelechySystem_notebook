# AI代理运作参数映射与流程Skill规范-备忘-20260320-001

日期：2026-03-20

摘要：
本备忘记录要点：将“节点参数传参”与“流程级映射”作为一个独立的运作（management）Skill，供业务 Agent 在每次运行业务 Skill 之前调用，以自动生成/验证/写入目标 Skill 所需的 `params.json`，并保障路径规范化与运行环境（例如 `PYTHONPATH`）就绪。

一、背景与动机
- 目标：降低每次运行业务 Skill 时对手工 params.json 的依赖，统一参数 schema，便于 AI 自动生成与审计。
- 问题：业务 Skill 描述（`SKILL.md`）中常含参数占位，但运行时需要绝对路径、上下游映射与格式验证。

二、设计决策（核心结论）
- 将参数映射与验证逻辑抽象为独立的“运作 Skill”（Management Skill），而不是把这些逻辑写死到业务 Agent 中。
- Agent 的职责：决策与调用；运作 Skill 的职责：读取目标 Skill 的 `inputs`、收集上下文、标准化路径、生成并写入 `params.json`、返回就绪确认。
- 多节点流程（flow）支持：在 flow-level Skill 中声明 `flow_nodes` 或 `flow_mapping`，运作 Skill 根据 `workflow_state.json` 自动填充下游 node 的 `params.json`。

三、运作 Skill （规范要点）
1. 输入（示例）
  - `target_skill`：目标业务 Skill 名称（例如：学术科研：关键词语义预筛选文献条目）
  - `task_dir`：当前任务文件夹绝对路径
  - `flow_mapping`（可选）：上游输出字段 → 下游输入字段 的映射表
2. 行为
  - 读取目标 Skill 的 `SKILL.md`，解析 `inputs`（字段名、类型、required）
  - 检查 `task_dir/workflow_state.json`、用户显式参数（对话或临时 JSON）
  - 执行路径标准化：把相对路径转换为绝对路径（基于 `task_dir` 或工作区根）
  - 按 `flow_mapping` 把上游输出字段映射到下游需要的输入字段
  - 验证必填字段，补全可选默认值（例如 `script: true`、`compare: false`）
  - 写入 `params.json`（位置可选：目标 Skill 目录或 `task_dir`），并备份老版本（如存在则重命名为 `params.json.bak.YYYYMMDD_HHMM`）
  - 返回变更清单（已变更字段、文件路径、下一步建议命令）
3. 输出规范（示例）
  - JSON 对象：{ "updated_fields": [...], "params_path": "...", "next_step": "run skill ..." }

四、多节点流程示例（flow_mapping）
- `flow_mapping` 示例（JSON）：
{
  "node_prescreen": {
    "output_review_csv": "prescreen_review_csv"
  },
  "node_read": {
    "source_csv": "prescreen_review_csv",
    "topic": "topic"
  }
}
- 说明：运作 Skill 在 node_prescreen 运行完并写入 `workflow_state.json` 后，会把其 `review_candidates.csv` 的绝对路径填入 node_read 的 `params.json.source_csv`。

五、操作与运行要求
- 环境要求：若业务 Skill 依赖本地包（如 `autodokit`），需确保 `PYTHONPATH` 包含对应根目录或使用虚拟环境并激活。
- 路径要求：业务事务中所有文件路径应使用绝对路径传递；运作 Skill 负责转换。
- 备份策略：覆盖写入 `params.json` 前自动保存备份，便于回滚。

六、示例工作流（Agent 调用顺序）
1. Agent 收到用户指令（自然语言或参数 JSON）。
2. Agent 调用运作 Skill：传入 `target_skill` + `task_dir` +（可选）`flow_mapping`。
3. 运作 Skill 解析并写入 `params.json`，返回就绪信息。
4. Agent 按返回的 `next_step` 顺序调用业务 Skill（或直接执行 `python 语义预筛选.py <params>`）。
5. 若为多节点流程，Agent 在每个节点后更新 `workflow_state.json`，并再次调用运作 Skill 为下游节点生成参数。
