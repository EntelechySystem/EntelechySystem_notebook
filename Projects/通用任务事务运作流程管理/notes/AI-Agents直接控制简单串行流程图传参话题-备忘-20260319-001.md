# AI-Agents直接控制简单串行流程图传参话题-备忘-20260319-001


## 一、目标（简述）
规范流程 Skill 与节点 Skill 之间的参数传递，支持两种单节点传参方式（对话写入 params.json / 预先写好 params.json），并支持多节点串行时上游输出自动注入到下游节点 params.json 的流程化实现。

---

## 二、术语约定
- 节点（node）：绑定一个 Skill 的最小执行单元。
- Task 文件夹：每个 task 对应一个文件夹，存放该 task 的输出（如 `target_dir`）。
- 全局共享资源：跨 task 共用的文件夹（如文献总库 `source_csv`）。
- `params.json`：每个节点的参数文件，节点执行前由 AI 或用户写入/覆盖（需备份）。
- `workflow_state.json`：流程运行时的状态记录（上游节点 outputs 的绝对路径），供下游自动拾取。

---

## 三、单节点传参方式（两种）
1. 方式 A — 对话临时传参（推荐单节点或调试时使用）
   - 用户在对话中以 JSON 提供实参。
   - Agent 行为：校验必填项 → 备份现有 `params.json`（若有） → 写入新的 `params.json` → 执行该节点 Skill。
   - 优点：灵活、便于快速迭代；缺点：需在对话中重复提供路径/配置。

2. 方式 B — 预写 `params.json`（推荐稳定/重复运行）
   - 用户事先在节点目录下写好完整 `params.json`。
   - Agent 行为：直接读取该文件并执行；若缺字段则在对话询问补全或中止。
   - 优点：对运行复现友好；缺点：修改不如对话方式灵活。

必需字段（示例）：`topic`、`source_csv`、`target_dir`  
可选字段：`script`（bool）、`compare`（bool）、`top_k`、`year_range` 等。

示例 `params.json`：
{
  "topic": "房地产业对银行系统性金融风险的影响",
  "source_csv": "C:\\...\\references_data\\文献数据库\\总库\\文献数据表.csv",
  "target_dir": "C:\\...\\tasks\\EXP_20260319_001",
  "script": true,
  "compare": true
}

写入前请先备份：`params.json.bak_YYYYMMDD_HHMMSS`

---

## 四、多节点串行（流程内传参）设计要点
1. 在流程 Skill 中声明节点映射（`flow_nodes`），明确上游输出名与下游输入名的映射。例如（YAML 示意）：
flow_nodes:
  - id: prescreen
    skill: 学术科研：关键词语义预筛选文献条目
    outputs:
      review_candidates: review_candidates.csv
      prescreen_report: prescreen_report.json
  - id: downstreamA
    skill: 下游SkillA
    inputs_from:
      source_csv: prescreen.outputs.review_candidates
      prev_report: prescreen.outputs.prescreen_report

2. 运行时行为（Agent）
   - 运行到某节点时，从 `flow_nodes` 和当前 `workflow_state.json` 解析所需上游值。
   - 将映射后的实参写入该节点的 `params.json`（先备份旧文件）。
   - 执行节点（按单节点方式），执行结束后将关键输出路径写入 `workflow_state.json`。

3. `workflow_state.json` 格式示例：
{
  "prescreen": {
    "output_dir": "C:\\...\\tasks\\EXP_20260319_001\\prescreen_script_output",
    "review_candidates": "C:\\...\\prescreen_script_output\\review_candidates.csv",
    "prescreen_report": "C:\\...\\prescreen_script_output\\prescreen_report.json"
  }
}

4. 错误与缺项处理
   - 若上游输出未生成，Agent 必须中止并在对话中询问用户（不得随意猜测路径或继续运行）。
   - 当写入 `params.json` 失败或脚本导入失败，应打印诊断信息并回滚 `params.json`（使用备份文件）。

---

## 五、Agent 与用户对话模版（可直接拷入对话）
1. 写入并运行单节点（对话传参样例）：
请将以下 JSON 备份写入 `.github/skills/<Node>/params.json` 并运行该 skill：
{ "topic": "...", "source_csv": "C:\\...\\文献数据表.csv", "target_dir": "C:\\...\\tasks\\EXP_001", "script": true, "compare": true }
执行后请返回 `"review_candidates.csv"` 的绝对路径并更新 `workflow_state.json`。

2. 多节点串行（示例）：
- “现在执行流程 `流程XYZ` 的节点 `prescreen`：请把上游参数写入 `prescreen` 的 `params.json`（先备份），运行后把输出路径写入 `workflow_state.json`，然后继续执行下一个节点 `downstreamA`（若 `downstreamA` 的 `params.json` 需要上游输出，请自动填入）。”

---

## 六、文件与路径规范（建议）
- 参数中优先使用绝对路径或以 workspace 根为基准的统一相对路径（避免环境差异）。
- `params.json` 写入规则：校验 → 备份 → 写入 → 记录修改日志（简短文本）。
- `workflow_state.json` 存放位置建议：流程根目录下（例如 `workflow_state.json`），Agent 执行期间更新。

---

## 七、建议与注意事项
- 在多人协作时，把 `flow_nodes` 映射与 `workflow_state` 规范写入流程 Skill 的 SKILL.md 文档顶部，便于 Agent 与人类理解。
- Agent 写入/覆盖 `params.json` 必须有“备份与回滚”逻辑。
- 在需要高可重复性的实验中，记录每次运行的 `params.json.bak` 和 `workflow_state.json` 快照。
- 对于 `compare` 判定阈值、输出格式（CSV 列名、编码）等在 SKILL.md 中标准化，避免下游解析错误。
