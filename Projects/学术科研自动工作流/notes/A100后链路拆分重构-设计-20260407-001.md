# A100后链路拆分重构-设计-20260407-001

## 一、设计背景

当前普通文献阅读主链已经形成 A080 -> A090 -> A095 -> A100 的最小可运行闭环，但其中 A100 节点承担了过多不同抽象层次的职责，导致节点边界不清、后续扩展困难。

目前 A100 同时做了以下几类动作：

1. 为待研读文献触发普通文献精解析资产生成。
2. 读取精解析结果并形成单篇深读笔记。
3. 直接修订五类主题级分析笔记。
4. 直接补写创新点笔记。
5. 从深读文献的参考文献中发现新候选并回流主链。

这意味着 A100 同时覆盖了：

1. 证据资产准备层。
2. 单篇批判性研读层。
3. 跨文献综合分析层。
4. 研究设计启发层。

这四层不是同一种工作。若继续把它们压在同一节点中，后续会持续出现以下问题：

1. 一个节点同时修改过多产物，难以审计和回滚。
2. 单篇深读与跨文献综合互相耦合，难以独立优化。
3. 创新点笔记容易被单篇文献的偶然启发驱动，而不是由跨文献综合证据驱动。
4. 无法稳定承接“带着批判思维做研读笔记，再服务开题报告”的目标。

因此，需要对 A100 之后的链路做拆分重构。

## 二、设计目标

本次设计只讨论 A100 及其后续链路，明确冻结 A080、A090、A095 的现有职责与实现。

本设计目标如下：

1. 不改动 A080、A090、A095 的职责、状态机语义和现有实现。
2. 把当前 A100 拆分为“精解析资产化”和“批判性研读写笔记”两层。
3. 让单篇深读产物与跨文献综合产物分层生成，避免单节点越权。
4. 将主题级分析笔记与创新点笔记的正式修订后移到 A110、A120、A130、A140 等综合节点。
5. 使重构后的链路更符合真实科研工作流：泛读筛选、精解析准备、批判性研读、跨文献综合、研究设计收束。

## 三、设计边界

### 3.1 本次明确不改动的部分

以下内容在本次设计中视为冻结，不做职责改写：

1. A080：非综述候选入池、预处理、标准笔记骨架与待泛读落位。
2. A090：泛读、升级研读判断、轻量分析补写、新候选回流。
3. A095：批次汇总补写与面向深读的主题背景收束。
4. `literature_reading_state` 中 A080-A095 既有状态列与状态推进规则。

### 3.2 本次允许改动的部分

以下部分属于本次设计的可改动范围：

1. A100 的职责、输入输出与审计口径。
2. 新增 A105 节点的职责、输入输出与审计口径。
3. A110、A120、A130、A140 的职责边界与输入来源。
4. A100 之后的状态字段、产物契约与调度顺序。
5. A100 之后对应 agent、skill、affair、config、文档与 gate 设计。

## 四、核心设计结论

### 4.1 A100 不再承担“单篇研读 + 分析笔记修订 + 创新点更新”的混合职责

重构后，A100 只负责：

1. 消费 `pending_deep_read=1` 的当前态文献。
2. 生成或校验 `non_review_deep` 精解析资产。
3. 形成可供后续研读消费的单篇深读输入包。
4. 更新与精解析资产相关的状态与审计结果。

换句话说，A100 的定位是“精解析资产化节点”，不是“最终知识写回节点”。

### 4.2 新增 A105 作为“批判性研读与标准文献笔记”节点

A105 是本次重构的关键新增节点。

它负责：

1. 基于 A100 的精解析资产执行单篇批判性研读。
2. 生成或修订标准文献笔记。
3. 明确记录以下单篇层面的研读内容：
   1. 文献基本信息。
   2. 核心观点与研究方法。
   3. 假设条件。
   4. 数据、模型、识别策略或案例证据的局限。
   5. 对当前论文或研究主题的参考价值。
   6. 个人疑问与启发。
4. 产出回流检索所需的新关键词、新候选与推荐理由。
5. 完成单篇层面的证据闭环与审计闭环。

### 4.3 五类分析笔记不再由 A100/A105 直接正式修订

当前 A100 内嵌的以下职责应迁出：

1. 对五类分析笔记的正式修订：领域研究脉络、核心成果、争议点、未来方向、领域知识框架。
2. 创新点笔记新增或更新。

迁出后的职责分配建议如下：

1. A110：跨文献结构化比较与文献矩阵。
2. A120：领域研究脉络、核心成果、争议点、未来方向。
3. A130：领域知识框架。
4. A140：创新点池或创新点笔记的正式更新。

### 4.4 本次不是简单重命名，而是按抽象层次重新切节点

本次设计不是把原 A100 的代码拆成两个文件而已，而是按“证据准备 -> 单篇认知加工 -> 跨文献综合 -> 研究设计抽象”的顺序重排节点。

因此，它属于链路重构，而不是局部修补。

## 五、面向科研研读要求的映射

### 5.1 分层阅读策略的节点映射

根据“核心文献精读、相关文献泛读、边缘文献略读”的要求，链路映射建议如下：

1. A080：候选入池与预处理。
2. A090：相关/边缘文献的泛读、略读与升级筛选。
3. A095：一批泛读结果的主题背景收束。
4. A100：对升级为核心文献的条目准备深读输入资产。
5. A105：核心文献的批判性研读与标准文献笔记。

### 5.2 批判性阅读习惯的节点映射

A105 应明确围绕以下问题做笔记，而不是只摘录内容：

1. 这个结论的假设条件是什么。
2. 数据或模型是否存在局限。
3. 有没有相反案例或未覆盖场景。

这些问题的输出应留在单篇标准文献笔记中，不应跳步写成主题级定论。

### 5.3 结构化读书笔记的节点映射

A105 的标准文献笔记应至少固定包含：

1. 作者、期刊、年份、题名。
2. 核心观点与研究问题。
3. 理论模型或解释机制。
4. 数据、方法与识别策略。
5. 结论与边界。
6. 对当前课题的参考价值。
7. 个人疑问与启发。
8. 新检索线索与可能回流候选。

### 5.4 动态补充文献的节点映射

“检索 - 研读 - 再检索”的闭环继续保留，但职责调整为：

1. A090 可从泛读中发现新候选并回流。
2. A105 可从批判性研读中发现更高质量的新候选并回流。
3. 回流统一回到 `pending_preprocess=1`，而不是直接绕过主链。

## 六、重构后的目标节点结构

### 6.1 目标顺序

冻结 A080-A095 后，目标顺序建议调整为：

1. A080：非综述候选与预处理。
2. A090：文献泛读与轻量分析。
3. A095：泛读批次分析汇总。
4. A100：文献精解析资产化。
5. A105：文献研读与标准文献笔记。
6. A110：文献矩阵与跨文献结构化比较。
7. A120：研究脉络、核心成果、争议点、未来方向。
8. A130：领域知识框架。
9. A140：创新点池或创新点笔记更新。

### 6.2 节点职责摘要

#### A100

职责：

1. 只负责 deep parse 资产生成、校验与登记。
2. 不直接写标准文献笔记。
3. 不直接 patch 五类分析笔记。
4. 不直接更新创新点笔记。

#### A105

职责：

1. 只负责单篇批判性研读。
2. 只写标准文献笔记与单篇证据产物。
3. 允许生成新候选回流信号。
4. 不直接生成主题级最终判断。

#### A110

职责：

1. 把 A105 标准文献笔记整理成矩阵与对比资产。
2. 为 A120-A140 提供结构化输入。

#### A120

职责：

1. 负责领域研究脉络。
2. 负责核心成果归纳。
3. 负责争议点与未来方向的综合。

#### A130

职责：

1. 负责领域知识框架。
2. 把跨文献知识组织成可支持研究设计的框架资产。

#### A140

职责：

1. 负责创新点池构建与创新点笔记正式更新。
2. 创新点应主要来自 A110-A130 的跨文献综合结果，而不是单篇偶发启发。

## 七、状态与契约调整建议

### 7.1 A100 与 A105 的状态拆分

为避免“精解析完成”与“研读完成”继续混在同一状态中，建议新增 A100-A105 之间的中间状态列。

建议新增：

1. `pending_deep_parse`：待精解析。
2. `in_deep_parse`：正精解析。
3. `deep_parse_ready`：精解析资产已完成。
4. `pending_critical_read`：待批判性研读。
5. `in_critical_read`：正批判性研读。
6. `critical_read_done`：批判性研读完成。

若当前阶段不希望大改已有 `pending_deep_read` 语义，也可采用兼容迁移策略：

1. 先让 A100 消费 `pending_deep_read=1`。
2. A100 完成后写 `deep_parse_ready=1`。
3. A105 消费 `deep_parse_ready=1 AND critical_read_done=0`。

### 7.2 分析与创新同步标记后移

现有以下标记建议从 A100 迁移到后续节点：

1. `analysis_formal_synced`：不再由 A100 写入，改由 A120/A130 分别写入更细分的同步标记。
2. `innovation_synced`：不再由 A100 写入，改由 A140 写入。

### 7.3 单篇笔记与综合笔记解耦

建议把笔记对象分为两层：

1. 单篇层：A105 标准文献笔记。
2. 综合层：A110-A140 的矩阵、脉络、框架、创新点。

这样可以避免单篇节点直接碰主题级综合资产。

## 八、实施原则

### 8.1 先改职责，不先追求命名完美

若短期内无法一次性完成 A100 -> A105 的所有代码、调度、文档与 agent 改造，可以先保证职责拆分真实生效，再逐步完成命名与文档统一。

### 8.2 先保证 A100 与 A105 的边界清晰，再下放综合职责

本次重构最关键的一刀是：

1. A100 只做精解析。
2. A105 只做单篇批判性研读。

只有这两层稳定后，A110-A140 才值得继续接管正式综合职责。

### 8.3 不因重构而破坏现有 A080-A095 主链

本次设计已经明确冻结 A080-A095，因此所有重构都必须以下列约束为前提：

1. 不改变 A080/A090/A095 的输入输出语义。
2. 不改变现有泛读升级与回流逻辑。
3. 不要求为重构 A100 之后链路而回头推翻前半链路实现。

## 九、结论

本设计的真实建议是：

1. 赞成把当前 A100 拆开。
2. 赞成新增 A105 承担批判性研读与标准文献笔记。
3. 赞成把五类分析笔记和创新点笔记的正式修订后移到 A110-A140。
4. 不赞成继续使用“临时互换粗解析/精解析阶段”这种补丁式方案。
5. 本次最优路径不是再修补 A100，而是正式把 A100 后链路切成“精解析 -> 研读 -> 综合 -> 创新”的分层结构。

本设计因此作为 A100 后链路重构的上位约束文档，后续计划、事务实现、agent/skill 描述与状态字段调整都应以此为准。
