# 探索实验实证子流程设计-思考-20260305-001

## 1. 需求分析和目标分析

### 1.1 需求分析
探索实验/实证流程具有“快速迭代 + 严格验证”双重需求：

1. 需要高频试错（探索性）。
2. 需要稳健结论（发表性）。
3. 需要从探索阶段平滑过渡到正式实证阶段。
4. 需要把每次尝试的输入、参数、结果、失败原因留痕。

### 1.2 目标分析
建立“E 状态机”覆盖探索 -> 验证 -> 固化三阶段：

1. 探索阶段追求发现潜在信号。
2. 验证阶段追求识别与稳健性。
3. 固化阶段追求复现和交付。

### 1.3 可行性与挑战
可行性：高。

1. 现有 `code/03_main_analysis`、`04_robustness`、`05_figures`、`06_tables` 可直接承接。
2. 现有计量代理与审计代理体系可做流程治理。

挑战：

1. 探索阶段容易出现选择性报告风险。
2. 探索参数漂移若无记录，难复现。
3. 结果叙述容易早于证据充分性。

## 2. 决策和计划

### 2.1 探索实验实证状态机（E1-E8）

1. E1 问题实例化（从研究问题生成可检验假设）。
2. E2 数据可用性检查（变量可观测与样本可得）。
3. E3 探索性估计（多规格试跑与初筛）。
4. E4 诊断与筛查（识别前提、异常、可解释性）。
5. E5 正式估计（确定主规格并固定口径）。
6. E6 稳健性/异质性/机制检验。
7. E7 结果叙述与图表输出。
8. E8 审计固化（治理 + 复现 + 发布）。

### 2.2 路由与回退

主线：E1 -> E2 -> E3 -> E4 -> E5 -> E6 -> E7 -> E8

回退线：
1. E2 失败 -> 回 E1（重定义变量/假设）或回检索补数据。
2. E4 失败 -> 回 E3（重跑探索）或回 E2（补数据）。
3. E6 失败 -> 回 E5（主规格重设）或回 E1（假设重构）。
4. E8 失败 -> 按失败类型回 E5/E6/E7。

### 2.3 双模式运行

探索模式（exploratory）：
1. 目标：发现潜在关系和可行规格。
2. 特点：允许更高回退率，强调日志完整。
3. 禁止：直接写入最终结论。

正式模式（formal）：
1. 目标：形成可发表、可复现结论。
2. 特点：固定规格、强审计、强留痕。
3. 输出：进入论文正文与审稿材料。

### 2.4 与现有命令映射

1. E1-E2：`run-rag-econometrics-pipeline` 前置设计段。
2. E3-E4：`econometrics-analyst` + `data-engineer`。
3. E5-E6：`empirical-suite-executor` + 稳健性脚本。
4. E7：`run-scholar-analyze-results` + `writing-editor`。
5. E8：`whitelist-auditor` + `reproducibility-auditor`。

## 4. 监控和调整

### 4.1 监控指标

1. 探索效率：每轮从 E1 到 E5 的平均时长。
2. 规格稳定性：E5 后重新改规格比例。
3. 稳健通过率：E6 通过比例。
4. 复现通过率：E8 复现审计通过比例。
5. 选择性报告风险：被审计标记的风险项数量。

### 4.2 调整机制

1. 若 E3-E4 高频失败：前移数据与变量可行性检查。
2. 若 E6 高频失败：加强主规格确立标准，减少过拟合探索。
3. 若 E8 高频失败：把留痕模板内嵌到 E3-E7 每一步。

### 4.3 本轮结论

探索实验/实证应采用“先探索、再锁定、后审计”的分层状态机。通过 E1-E8 设计，可在保证探索效率的同时，抑制选择性报告风险，并提高最终可复现与可发表性。
