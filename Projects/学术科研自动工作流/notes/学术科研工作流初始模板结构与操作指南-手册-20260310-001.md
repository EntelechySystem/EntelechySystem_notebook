# 学术科研工作流初始模板结构与操作指南-手册-20260310-001

## 1. 目标与适用范围

本手册用于定义 `AcademicResearch-auto-workflow` 作为“学术科研工作流初始模板”时，必须保留的目录结构、文件职责和标准操作流程。

适用对象：

- 模板维护者
- 新项目初始化执行者
- 负责仓库治理与审计的代理

## 2. 模板应有结构清单

### 2.1 根目录必留文件

- `README.md`：模板说明与快速开始
- `AGENTS.md`：项目级代理入口说明
- `opencode.json`：OpenCode 权限与执行约束
- `pyproject.toml`：Python 项目与 CLI 入口定义
- `pyrightconfig.json`：类型检查配置
- `.gitignore`：忽略规则
- `.gitattributes`：文本与换行规则

### 2.2 根目录必留文件夹

- `.opencode/`：办公区与工作流控制层
- `.github/`：仓库级规则、文档、配置
- `academicresearch_kit/`：正式执行内核
- `config/`：全局配置与调度映射
- `code/`：分析代码工作区（按阶段）
- `data/`：数据分层目录（`raw/interim/clean`）
- `database/`：任务库、文献库、知识库
- `references/`：文献原始层与规范层
- `results/`：图表和结果产物
- `paper/`：论文正文与附录
- `review/`：审稿与修订材料
- `logs/`：运行与审计日志
- `docs/`：用户向文档

### 2.3 `.opencode/` 必留结构

- `agents/`：代理定义
- `skills/`：技能定义
- `workflows/`：工作流模板
- `commands/`：命令入口
- `rules/`：治理规则
- `governance/`：治理约束
- `prompts/`：提示词体系
- `library.md`：办公区总览

### 2.4 `.github/notes/` 推荐结构

- `manual/`：操作手册
- `plan/`：计划文档
- `report/`：报告文档
- `paper/`：理论文档
- `tasks/`：任务文档（按需）
- `memos/`：备忘录（按需）

## 3. 目录职责约束

- `data/` 必须遵循单向流：`raw -> interim -> clean`
- `references/` 统一管理文献资产：`origin/` 与 `normal/`
- `results/` 只放结果产物，不放核心业务逻辑
- `review/` 只放评审过程材料
- `logs/` 只放可追溯运行痕迹
- `academicresearch_kit/` 只放可复用、可测试的执行能力

## 4. 初始化操作指南

### 4.1 开局先接入百炼（OpenCode 启动前）

你当前场景是“模板开局就接入百炼”，推荐在 OpenCode 启动前完成以下两步：

1. 在仓库内放置密钥文件：`.github/config/bailian-api-key.txt`（仅第一行写 API Key）。
2. 确保密钥文件不会被提交到仓库（建议在 `.gitignore` 中加入 `.github/config/bailian-api-key.txt`）。

可选（仅当前 PowerShell 会话生效）：

```powershell
$env:DASHSCOPE_API_KEY = (Get-Content .github/config/bailian-api-key.txt -TotalCount 1).Trim()
```

### 4.2 OpenCode 启动后立即执行（推荐）

启动 OpenCode 后，优先执行 `/run-model-routing`，并显式传入：

- `api_key_file=.github/config/bailian-api-key.txt`
- `task_type=general`
- `quality_tier=balanced`
- `budget_level=normal`
- `latency_level=medium`
- `risk_level=low`
- `prompt=请回复OK`

```powershell
/run-model-routing api_key_file=.github/config/bailian-api-key.txt task_type=general quality_tier=balanced budget_level=normal latency_level=medium risk_level=low prompt="请回复OK"
```

一键接入（推荐）：

```powershell
uv run ark-opencode-bailian-bootstrap --project-root . --api-key-file .github/config/bailian-api-key.txt --execute
```


说明：

- 这一步会调用 `model-routing-dispatch`。
- 若启用执行，会按主模型与回退模型链路尝试百炼兼容接口。
- 路由计划与留痕会写入 `review/plan/model-routing-plan.md`。
- 路由计划与留痕会写入 `logs/run/model-routing-decision-log.md`。
- 路由计划与留痕会写入 `logs/audit/model-routing-cost-quality-audit.md`。
- 统一流程轨迹会写入 `logs/run/opencode-flow-trace-YYYY-MM-DD.jsonl`。

生效判据（必须同时满足）：

- 返回结果 `mode=live-call`。
- `invocation.status=PASS`。
- `selected_model` 非空（例如 `qwen3-max`）。
- `logs/run/opencode-flow-trace-YYYY-MM-DD.jsonl` 中出现 `provider=aliyun-bailian` 的事件记录。

### 4.3 不经过命令层的直接调用（最快）

如果你想不走命令编排，直接验证“可路由 + 可实连”，可用下面命令。

先做 decision-only（不发起真实模型调用）：

```powershell
uv run python .opencode/skills/model-routing-dispatch/scripts/run_model_routing_dispatch.py --api-key-file .github/config/bailian-api-key.txt --task-type general --quality-tier balanced --budget-level normal --latency-level medium --risk-level low --workspace-root .
```

再做 live-call（真实调用百炼）：

```powershell
uv run python .opencode/skills/model-routing-dispatch/scripts/run_model_routing_dispatch.py --api-key-file .github/config/bailian-api-key.txt --task-type general --quality-tier balanced --budget-level normal --latency-level medium --risk-level low --execute --prompt "请回复OK" --workspace-root .
```

### 4.4 启动前还是启动后使用

- 启动前：只做密钥文件就位与忽略规则配置。
- 启动后：执行 `/run-model-routing` 或上面的脚本命令完成首轮路由/实连。
- 建议策略：每个新任务开始时先跑一次 `decision-only`，在需要真实生成内容时再加 `--execute`。

### 4.5 可选的项目初始化（按需）

如需同时初始化任务库，可执行：

```powershell
uv run ark-taskdb-bootstrap --project-root .
uv run ark-taskdb-validate --project-root .
```

## 5. 日常操作指南

### 5.1 新任务启动

1. 在 `review/plan/` 记录任务目标与验收条件。
2. 在 `database/tasks/` 更新任务状态。
3. 通过 `scheduler-dispatch` 触发事务，不直接跳过调度层。

### 5.2 日志与审计

- 运行日志写入 `logs/run/`
- 审计日志写入 `logs/audit/`
- 每个里程碑至少做一次 `taskdb-replay`

### 5.3 结果固化

- 图表输出到 `results/figures/`
- 表格输出到 `results/tables/`
- 结论写入 `paper/sections/`，并在 `review/` 保留修订映射

## 6. 模板发布前检查清单

### 6.1 必删（模板发布必须执行）

- 删除运行依赖缓存：`.opencode/node_modules/`
- 删除运行日志：`logs/run/*`、`.opencode/logs/*`
- 删除临时/沙盒产物：`sandbox/*`、`demos/*` 中回归产物
- 删除运行态数据库日志：`database/tasks/execution_runs.jsonl`、`database/references/retrieval_bundles.jsonl`
- 确认 `git status` 干净

### 6.2 选删（按使用场景选择）

- 本地环境：`.venv/`
- IDE 痕迹：`.idea/`、`.vscode/`
- 打包元数据：`academic_research_kit.egg-info/`
- 锁文件：`uv.lock`（若希望模板发布时由使用者重新锁定）
- 用户上传真实数据与文献：`references/origin/user_uploads/*`

说明：

- 对外公开模板时，建议删除“选删”中的全部项目，避免携带本机与隐私痕迹。
- 若是团队内部继续在当前项目上迭代，可保留用户上传数据与文献目录。

## 7. 版本化建议

- 模板发布采用独立标签：`template-vYYYYMMDD`
- 每次发布必须附带一份 `report`，说明保留项、删除项、已知限制
- 不保留过时代码与文档，保持模板轻量且可直接启动
