# 普通文献泛读研读状态机理论模型与极简实现-设计-20260405-001

## 一、设计问题

这里要回答的问题不是“怎么再写一个阅读脚本”，而是：

1. 泛读和研读在通用学术科研范式下到底分别是什么。
2. 它们与标准文献笔记、分析笔记、创新点笔记之间的关系是什么。
3. 这种关系能否被流程化、状态机化和工程化。
4. 如何在保留理论完整性的前提下，先落一个快速可实现的极简版本。

结合通用学术科研经验，以及《博士论文通关指南：从文献研读至答辩，全程无坑实操手册》中对“泛读”和“研读”的区分，可以把普通文献阅读抽象成一个“双层阅读、三类笔记、两级分析循环”的理论模型。

## 二、核心结论

### 2.1 泛读的本质

泛读不是低质量阅读，而是带目的的筛选性阅读。

它回答的问题主要是：

1. 这篇文献是否与研究主题足够相关。
2. 它的主要贡献、方法、数据、结论是什么。
3. 它是否值得投入更高成本做深读。
4. 它是否暴露出下一批值得阅读的文献线索。

### 2.2 研读的本质

研读不是“把泛读读得更仔细一点”，而是带批判性的证据性阅读。

它回答的问题主要是：

1. 文献的论证链是否成立。
2. 隐含假设是什么。
3. 数据、模型、识别策略或案例证据有哪些局限。
4. 结论在哪些边界条件下可能失效。
5. 这篇文献对当前研究主题真正能贡献什么可用知识。
6. 它能否触发新的研究假设、机制命题或创新点。

### 2.3 分析笔记的本质

分析笔记不是单篇文献笔记的搬运容器，而是主题级综合资产。

它的职责是：

1. 比较多篇文献。
2. 归纳稳定命题。
3. 标出争议与边界。
4. 形成阶段性的研究判断。

因此，单篇标准文献笔记和主题级分析笔记不能混成同一层。

## 三、双层阅读、三类笔记、两级分析循环模型

### 3.1 双层阅读

双层阅读指：

1. 第一层：泛读层
2. 第二层：研读层

它们不是“轻重程度不同的同一动作”，而是目标不同的两类动作。

#### 3.1.1 泛读层

泛读层输出的是：

1. 相关性判断
2. 贡献概括
3. 方法与数据概况
4. 是否升级研读的决策
5. 下一批候选线索

#### 3.1.2 研读层

研读层输出的是：

1. 可回链的证据判断
2. 对方法、数据、结论的批判性理解
3. 对主题级分析笔记的正式修订
4. 对创新点笔记的更新

### 3.2 三类笔记

#### 3.2.1 标准文献笔记

这是单篇文献的主笔记。

它记录：

1. 文献信息
2. 研究问题
3. 理论或机制
4. 数据与方法
5. 核心结论
6. 局限性
7. 对当前主题的价值
8. 参考文献列表

#### 3.2.2 分析笔记

这是主题级笔记，不属于某一篇文献。

按当前管理要求，分析笔记固定为以下五类：

1. 领域研究脉络
2. 核心成果
3. 争议点
4. 未来方向
5. 领域知识框架

当前阶段补充约束：

1. 这五类分析笔记已经由前序事务建立。
2. 普通文献阅读链路只负责在既有文件上填充，不再创建新的分析笔记种类。
3. A090 是轻量补写，A095 是批次汇总补写，A100 是正式修订。

#### 3.2.3 创新点笔记

这是研究设计导向的笔记。

它不只是记录“想到一个点子”，而是记录：

1. 创新点候选
2. 触发来源文献
3. 作用机制或解释框架
4. 可行性疑问
5. 下一步验证任务

### 3.3 两级分析循环

#### 3.3.1 轻量分析循环

发生在泛读之后。

目标是：

1. 快速把一批文献中的新线索写进分析笔记。
2. 不做大规模重写，只做增量补写。
3. 为后续研读提供主题背景。

#### 3.3.2 正式分析循环

发生在研读之后。

目标是：

1. 用更高质量证据修订主题级判断。
2. 对已有分析笔记做正式 patch。
3. 把创新启发写入创新点笔记。

## 四、状态机表达

为了工程实现，可以把这个模型写成状态机。

### 4.1 文献对象状态

一篇普通文献可处于以下状态之一：

1. 已发现
2. 待预处理
3. 已预处理
4. 待泛读
5. 正泛读
6. 已泛读
7. 待研读
8. 正研读
9. 已研读
10. 失败待复核

### 4.2 笔记对象状态

与文献状态并行的，还有笔记状态：

1. 标准文献笔记骨架已创建
2. 标准文献笔记已泛读补写
3. 标准文献笔记已研读补写
4. 分析笔记轻量补写完成
5. 分析笔记正式修订完成
6. 创新点笔记已更新

### 4.3 状态转移原则

#### 4.3.1 泛读的状态转移

泛读遵循：

1. 待泛读 -> 正泛读
2. 正泛读 -> 已泛读
3. 正泛读 -> 待研读
4. 正泛读 -> 发现新候选 -> 待预处理

当前开发阶段采用简化约束：

1. 一篇文献默认只泛读一次。
2. 已泛读文献默认不再自动回到待泛读。

#### 4.3.2 研读的状态转移

研读遵循：

1. 待研读 -> 正研读
2. 正研读 -> 已研读
3. 正研读 -> 发现新候选 -> 待预处理

未来扩展时，可以允许：

1. 已研读 -> 待研读

但当前快速开发阶段可以不自动开放这条边，只保留人工触发的可能性。

## 五、泛读与研读对分析笔记的不同处理方式

这正对应前面讨论的“研读时怎么处理分析笔记”。

我的建议是把分析笔记更新分成两种模式。

### 5.1 泛读阶段：轻量补写

泛读阶段不重写分析笔记，只做以下动作：

1. 新增一个观察点
2. 新增一个潜在线索
3. 新增一个可疑争议点
4. 新增一个值得后续核验的命题

泛读阶段写进以下五类分析笔记的内容，应该更像：

1. 线索
2. 比较点
3. 待核验命题

而不应像：

1. 最终结论
2. 正式理论判断
3. 大段定稿式综述

### 5.2 研读阶段：正式修订

研读阶段才允许对分析笔记做正式 patch。

可以做的动作：

1. 修订已有命题的表述
2. 增加边界条件
3. 增加反例或证据不足说明
4. 将泛读阶段的猜测升级为正式判断
5. 删除被证据推翻的弱命题

因此，这里的最稳妥处理方式是：

1. 泛读只做轻量补写。
2. 研读才做正式修订。
3. 修订对象固定为以下五类分析笔记：领域研究脉络、核心成果、争议点、未来方向、领域知识框架。

## 六、一个通用可实现的工程模型

从工程实现角度，可以把每篇文献处理为一个对象 $d$，研究主题处理为一个上下文 $T$。

定义四类操作：

$$
P(d) = 预处理
$$

$$
R(d, T) = 泛读
$$

$$
S(B, T) = 批量综合
$$

$$
D(d, T) = 研读
$$

其中：

1. $P$ 产生可读资产和笔记骨架。
2. $R$ 产生粗筛决策和轻量分析增量。
3. $S$ 对一批泛读结果做主题级综合。
4. $D$ 产生正式证据判断和知识回写。

因此，完整链路可以写成：

$$
d_0 \xrightarrow{P} d_1 \xrightarrow{R} d_2 \xrightarrow{S} d_3 \xrightarrow{D} d_4
$$

并允许在 $R$ 与 $D$ 之后产生新的候选文献集合 $C_{new}$，再回流到 $P$：

$$
C_{new} \xrightarrow{P} \text{进入下一轮}
$$

这就是一个可流程化的科研阅读状态机。

## 七、快速可实现的极简版本

为了快速开发，建议先落一个极简版，不一开始就做过于复杂的知识系统。

### 7.1 极简版规则

1. 泛读只做一次。
2. 研读当前只允许单次自动进入，重复研读以后再加。
3. 分析笔记分成“轻量补写”和“正式修订”两种动作。
4. 创新点笔记只做追加，不做复杂评分系统。

### 7.2 极简版笔记集合

极简版只维护三类文件：

1. 标准文献笔记
2. 分析笔记
3. 创新点笔记

其中分析笔记固定为以下五份既有文件：

1. 领域研究脉络
2. 核心成果
3. 争议点
4. 未来方向
5. 领域知识框架

这五份文件由前序事务提前建立，A090、A095、A100 只负责填写和修订。

### 7.3 极简版节点动作

#### A080

1. 解析 PDF
2. 生成标准笔记骨架
3. 回填 cite_key

#### A090

1. 逐篇泛读
2. 填写标准笔记的泛读部分
3. 决定是否进入 A100
4. 轻量补写既有五类分析笔记
5. 发现新候选并送回 A080

#### A095

1. 汇总一批泛读结果
2. 对既有五类分析笔记形成批次分析补充

#### A100

1. 逐篇研读
2. 正式修订标准笔记
3. 正式修订既有五类分析笔记
4. 更新创新点笔记
5. 发现新候选并送回 A080

## 八、为什么这个模型适合当前项目

这个模型有四个优点：

1. 它符合人类科研实际行为，而不是纯软件工程想象。
2. 它能被状态机化，因此可以进入 SQLite 当前态表和事件表。
3. 它区分了“轻量分析”和“正式分析”，正好解决分析笔记处理边界的模糊地带。
4. 它允许先做极简版，以后再把重复泛读、重复研读、在线检索、复杂创新点评分逐步加进来。

## 九、最终建议

最终建议可以收束为五条：

1. 把泛读定义为筛选性阅读，把研读定义为批判性证据阅读。
2. 把单篇标准文献笔记、主题级分析笔记、创新点笔记明确分层。
3. 把分析笔记更新分成泛读轻量补写和研读正式修订两种模式。
4. 把整个普通文献阅读主链实现成可回流的状态机。
5. 当前先落极简版：泛读只一次，研读先做单次自动进入，后续再扩展。
