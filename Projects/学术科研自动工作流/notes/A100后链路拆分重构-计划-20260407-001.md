# A100后链路拆分重构-计划-20260407-001

## 一、计划目标

基于 [design-A100后链路拆分重构-20260407-001](A100后链路拆分重构-设计-20260407-001.md) 的结论，制定一个只改动 A100 之后链路、不改动 A080-A095 的实施计划。

本计划目标是：

1. 让 A100 只做精解析资产化。
2. 新增 A105 做批判性研读与标准文献笔记。
3. 把五类分析笔记与创新点笔记的正式修订迁移到 A110、A120、A130、A140。
4. 在不破坏前半链路的前提下，逐步完成状态、事务、调度、agent、skill 和文档迁移。

## 二、范围与冻结项

### 2.1 冻结项

以下内容在本计划中不改动：

1. A080 affair、agent、skill、config 与状态推进语义。
2. A090 affair、agent、skill、config 与状态推进语义。
3. A095 affair、agent、skill、config 与状态推进语义。
4. A080-A095 已有导出物与审计口径。

### 2.2 改动范围

本计划允许改动：

1. A100 affair、agent、skill、config、状态字段与 gate。
2. 新增 A105 的 affair、agent、skill、config、状态字段与 gate。
3. A110、A120、A130、A140 的职责描述、输入输出契约与调度位置。
4. PA 编排配置、设计文档、计划文档与相关 API/README 同步。

## 三、分阶段实施计划

### 阶段一：完成设计冻结与责任切分

#### 目标

先把理论边界锁定，避免进入代码阶段后继续反复改问题定义。

#### 任务

1. 确认 A080-A095 冻结不动。
2. 确认 A100 改为“精解析资产化节点”。
3. 确认新增 A105 作为“批判性研读与标准文献笔记节点”。
4. 确认五类分析笔记与创新点笔记正式修订迁出 A100/A105。
5. 确认 A110/A120/A130/A140 的目标职责分配。

#### 预期结果

1. 形成稳定设计文档。
2. 后续实现不再回到“是否要改 A080-A095”的讨论。

### 阶段二：状态机与配置契约调整

#### 目标

先把 A100 后链路需要的状态表达清楚，避免代码实现时职责仍然互相覆盖。

#### 任务

1. 设计 A100 与 A105 之间的状态过渡。
2. 评估是否新增以下字段：
   1. `pending_deep_parse`
   2. `in_deep_parse`
   3. `deep_parse_ready`
   4. `pending_critical_read`
   5. `in_critical_read`
   6. `critical_read_done`
3. 若需要兼容迁移，定义过渡口径：
   1. A100 暂时继续消费 `pending_deep_read=1`。
   2. A100 完成后写 `deep_parse_ready=1`。
   3. A105 再消费 `deep_parse_ready=1`。
4. 重新定义 `analysis_formal_synced` 与 `innovation_synced` 的写入节点。
5. 更新 A100、A105、A110-A140 的配置模板字段说明。

#### 预期结果

1. `literature_reading_state` 在 A100 后的语义清晰。
2. 每个节点消费什么、回写什么有稳定契约。

### 阶段三：A100 代码与 agent/skill 收缩

#### 目标

把现有 A100 从“混合节点”缩成“精解析节点”。

#### 任务

1. 修改 A100 affair：
   1. 保留 `non_review_deep` 精解析资产生成或校验。
   2. 去掉标准文献笔记正文写作职责。
   3. 去掉五类分析笔记 patch 职责。
   4. 去掉创新点笔记更新职责。
2. 调整 A100 输出物：
   1. 精解析资产目录。
   2. 资产登记记录。
   3. 面向 A105 的输入清单或索引。
3. 调整 A100 agent 文案、技能说明和 gate 审计项。
4. 更新 A100 config 示例与 API 文档。

#### 预期结果

1. A100 变成单一职责节点。
2. A100 的输出可以独立复用，不再直接耦合主题级笔记。

### 阶段四：新增 A105 研读节点

#### 目标

建立真正对应“批判性研读”的单篇节点。

#### 任务

1. 新建 A105 affair。
2. 定义 A105 输入：
   1. A100 输出的 deep parse 资产。
   2. 文献元数据。
   3. 已有 manual_guidance 与 reading_objective。
3. 定义 A105 输出：
   1. 标准文献笔记。
   2. 单篇批判性研读摘要。
   3. 新关键词或新候选回流信号。
4. 定义 A105 必须回答的批判性问题：
   1. 假设条件是什么。
   2. 数据或模型局限是什么。
   3. 有无相反案例或未覆盖场景。
5. 新建 A105 agent、skill、config 示例与 gate 审计规则。

#### 预期结果

1. 单篇深读笔记与批判性研读要求真正落地。
2. A105 成为后续 A110-A140 的主输入来源。

### 阶段五：A110-A140 职责迁移

#### 目标

把跨文献综合与创新抽象从单篇深读节点迁移出去。

#### 任务

1. A110：改为优先消费 A105 标准文献笔记，而非直接再读 raw text。
2. A120：承接领域研究脉络、核心成果、争议点、未来方向四项正式修订。
3. A130：承接领域知识框架正式修订。
4. A140：承接创新点池与创新点笔记正式更新。
5. 更新各节点的输入输出说明与审计项。

#### 预期结果

1. 五类分析笔记与创新点笔记不再由 A100 单点写入。
2. 后半链路形成“单篇 -> 综合 -> 创新”的合理分层。

### 阶段六：编排与文档同步

#### 目标

让新链路在编排层、文档层和说明层保持一致。

#### 任务

1. 更新 PA 默认顺序与节点图。
2. 更新 A100-A140 的 agent 文档。
3. 更新对应 skill 文档。
4. 更新 API 手册中 A100 后链路契约。
5. 补充设计文档、计划文档与必要的迁移说明。

#### 预期结果

1. 编排层与实现层一致。
2. 用户和后续智能体不会继续把 A100 当成旧的混合节点使用。

### 阶段七：回归验证与迁移验收

#### 目标

确保重构后链路可运行、可解释、可审计。

#### 任务

1. 用一批已有 `pending_deep_read=1` 的文献验证 A100 是否只产 deep parse 资产。
2. 验证 A105 是否能正确生成标准文献笔记与回流信号。
3. 验证 A110-A140 是否能按新职责消费 A105 产物。
4. 验证 A080-A095 在整个重构过程中没有被破坏。
5. 做一次端到端审计：状态写入、产物路径、gate 结果、日志记录是否闭环。

#### 预期结果

1. 后半链路在工程上真正可跑。
2. 新职责分层不仅写在文档里，也体现在运行结果里。

## 四、实施优先级

建议优先级如下：

1. 第一优先级：A100 缩责 + A105 新增。
2. 第二优先级：状态字段与配置契约补齐。
3. 第三优先级：A110-A140 输入输出迁移。
4. 第四优先级：agent/skill/API/README 文档统一。

原因是：

1. 不先切开 A100，就无法真正建立 A105。
2. 不先建立 A105，就无法让 A110-A140 有正确的上游输入。
3. 不先让代码职责变化真实生效，文档与 agent 文案只会继续滞后。

## 五、风险与应对

### 风险一：A110-A140 当前实现还不足以完全接管正式综合

应对：

1. 先完成 A100/A105 切分。
2. 再逐步增强 A110-A140，不要求一次到位。

### 风险二：状态字段调整可能影响现有运行脚本

应对：

1. 采用兼容迁移字段。
2. 先新增字段，不立即删除旧字段。

### 风险三：A100 缩责后短期内会出现“深读完成但未综合”的中间阶段

应对：

1. 把这种中间态视为正常、可审计状态。
2. 用 A105 -> A110 的后续节点承接，不再强行在 A100 内部闭环。

### 风险四：文档、agent、skill 与代码不同步

应对：

1. 将文档同步纳入正式阶段任务，而不是实现后再补。
2. 每完成一阶段，就同步对应节点说明。

## 六、验收标准

本计划完成后，应满足以下验收口径：

1. A080-A095 没有职责或代码改动。
2. A100 不再直接修订五类分析笔记和创新点笔记。
3. A105 已成为独立的批判性研读节点。
4. A110-A140 已明确接管各自的综合职责。
5. 新链路可以表达“检索 - 泛读 - 精解析 - 研读 - 综合 - 创新”的分层流程。
6. 对开题报告所需的文献综述、研究空白、知识框架与创新点支持能力明显增强。

## 七、结论

本计划不追求一次性大爆炸改造，而采用“冻结前半链路、重构后半链路、分阶段迁移综合职责”的稳妥路线。

按该计划推进，能够在不破坏现有 A080-A095 主链的前提下，把当前过载的 A100 拆分成更符合科研工作流的后半链路，为后续服务开题报告与研究设计打下结构化基础。
