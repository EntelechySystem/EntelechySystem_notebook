# 知识管理子流程设计-思考-20260305-001

## 1. 需求分析和目标分析

### 1.1 需求分析
学术科研中的知识管理不仅是“存文献”，还包括概念、变量、方法、证据、结论与审稿意见的联动管理。当前需要建立知识管理子流程，解决：

1. 文献笔记与研究问题脱节。
2. 变量定义与文献证据不可追溯。
3. 结果结论与证据引用链断裂。
4. 修订意见难以映射到具体证据与分析动作。

### 1.2 目标分析
建立“知识资产状态机”，让知识管理成为可执行流程，而非静态仓库。

1. 形成知识资产分层模型（原始 -> 规范 -> 结构化 -> 可用知识）。
2. 形成知识路由（采集、抽取、对齐、校验、复用）。
3. 形成知识审计（可追溯、一致性、版本化）。
4. 与主科研流程（N1-N12）形成双向映射。

### 1.3 可行性与挑战
可行性：高。

1. 现有 `references/normal/manifest`、`notes`、`paper/sections` 已具备基础。
2. 已有文献检索代理和写作代理可承接知识加工。

挑战：

1. 知识粒度不统一（论文级、段落级、变量级）。
2. 若无统一 ID 与版本策略，难以稳定复用。
3. 文献证据与实证结论需要跨目录映射。

## 2. 决策和计划

### 2.1 知识管理状态机（建议）

建议节点：
1. K1 知识采集（文献、笔记、外部资料）。
2. K2 知识规范化（题录、标签、格式、引用键）。
3. K3 知识抽取（研究问题、方法、变量、结论、局限）。
4. K4 知识对齐（与当前课题问题和变量映射）。
5. K5 知识验证（证据强度与冲突检查）。
6. K6 知识发布（进入可复用知识库并供主流程调用）。

### 2.2 核心路由

1. 新增文献 -> K1 -> K2 -> K3 -> K4 -> K5 -> K6
2. 若 K4 不匹配当前课题 -> 回 K1 或进入候选池
3. 若 K5 冲突未解 -> 回 K3 重新抽取并标注冲突
4. K6 输出后可被 N1/N3/N7/N11 调用

### 2.3 与现有资产映射

1. K1/K2：`references/origin/`、`references/normal/bib/`、`references/normal/manifest/`
2. K3：`references/normal/notes/`
3. K4/K5：`review/plan/knowledge-alignment.md`
4. K6：`docs/knowledge/`（建议新增）或 `references/normal/notes/knowledge-index.md`

### 2.4 审计要求

1. 每条知识条目必须有来源路径与时间戳。
2. 每个关键结论必须有证据强度标签（A/B/C）。
3. 冲突条目必须显式保留，不得直接覆盖。
4. 知识版本必须可追溯到具体变更。

## 3. 任务分配

### 3.1 分配给任务运作智能体

任务 A：知识条目标准化模板
1. 内容：定义知识条目字段（主题、方法、变量、证据、冲突、可复用场景）。
2. 产物：知识条目模板文档。

任务 B：知识索引构建
1. 内容：从 `references/normal/notes/` 自动聚合知识索引。
2. 产物：`knowledge-index.md`。

任务 C：主流程映射
1. 内容：将 K 节点映射到 N1/N3/N7/N11 的调用关系。
2. 产物：知识调用映射图。

任务 D：知识审计脚手架
1. 内容：实现冲突记录、证据等级检查、引用可追溯检查。
2. 产物：`logs/audit/knowledge-audit-*.md` 模板。

## 4. 监控和调整

### 4.1 监控指标

1. 知识可追溯率：条目可追溯到原文路径比例。
2. 知识复用率：被 N 节点复用的知识条目比例。
3. 冲突显式率：冲突条目中被显式标记的比例。
4. 过期率：长期未更新且仍被调用条目占比。

### 4.2 调整机制

1. 若复用率低：收敛抽取字段并增强索引检索。
2. 若冲突高：增加方法与变量口径标准化规则。
3. 若追溯率低：禁止无来源条目进入 K6。

### 4.3 本轮结论

知识管理应作为独立子流程运行，不附属于“文献管理”单点。通过 K1-K6 状态机，可将知识资产从静态文件升级为可审计、可复用、可回退的科研基础设施。

## 5. 补充：K1 与检索流程关系、双分支设计与 AOK 接入

### 5.1 K1 与检索关系（关键澄清）

K1 不等于“再检索一次”，而是“接收检索结果并知识化”。

1. 检索流程输出原始对象与基础元数据。
2. K1 将原始对象转为知识条目，进入 K 状态机。
3. 两者是串联关系：`检索 R 状态机 -> K1`。

### 5.2 知识管理双分支

知识管理建议明确拆为两类并行分支：

1. 文献管理分支（KM-L）
- 目标：把文献对象转为“可引用、可对齐、可复用”的知识资产。
- 重点：题录、原文、笔记、证据等级、冲突记录。

2. 数据管理分支（KM-D）
- 目标：把数据对象转为“可解释、可复现、可建模”的知识资产。
- 重点：变量字典、口径版本、预处理谱系、可识别性备注。

### 5.3 文献管理是否参考 AOK 事务

可以，且建议“优先复用，缺口自建”。

1. 优先复用 AOK 已有事务思想：
- 导入与预处理文献元数据
- 合并去重文献元数据
- 合并去重 bibtex
- 从 PDF 提取可检索文本
- 解析与分块

2. 若现有事务不足，可新增 AOK 文献事务：
- `文献证据等级评定`
- `文献冲突对账`
- `变量-文献映射生成`
- `研究问题-证据覆盖检查`

### 5.4 数据管理的 AOK 事务建议

建议新增或复用以下事务族：

1. `数据源台账生成`
2. `变量字典自动对齐`
3. `口径版本差异比较`
4. `预处理谱系记录`（raw->interim->clean）
5. `可识别性前置检查`

### 5.5 执行责任（Agent）

1. 文献管理主责 Agent：`cn-literature-retriever`（配合 `writing-editor` 进行结构化抽取）。
2. 数据管理主责 Agent：`cn-data-retriever` + `data-engineer`。
3. 路由与调度主责 Agent：`orchestrator`。
4. 审计主责 Agent：`whitelist-auditor` + `reproducibility-auditor`。

### 5.6 接口建议

K1 输入统一接受 `retrieval_bundle`，并输出 `knowledge_bundle`：

1. `knowledge_id`
2. `origin_bundle_id`
3. `knowledge_type`（literature/data）
4. `tags`（主题/方法/变量）
5. `evidence_level`
6. `conflict_flags`
7. `publish_state`（candidate/validated/rejected）

### 5.7 补充结论

K1 与检索的关系应定义为“检索供给层 -> 知识管理接收层”。知识管理必须双分支（文献管理、数据管理），并采用“能复用 AOK 事务就复用，缺口再自建事务”的策略，由专门 Agent 执行，`orchestrator` 统一调度。
