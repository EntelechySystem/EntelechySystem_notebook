# A070综述精读与分析笔记理论设计-设计-20260404-001

## 一、设计背景

A070 不是一个以“生成更多文件”为目标的节点，而是一个以“围绕既有综述资产做高质量精读与综合分析”为核心的节点。

它同时具备两种属性：

1. 固定流程型事务：必须按既定顺序遍历综述待读队列、读取解析资产、写单篇标准文献笔记、再写跨综述分析笔记、最后生成提供给 A080 的非综述类待读清单。
2. 分析型事务：不能只做字段搬运、句子摘抄或规则拼接，而必须围绕研究问题、研究脉络、共识与争议、未来方向和知识框架做真正的学术性综合判断。

当前主要问题不在于“没有解析结果”，而在于“没有把解析产物分层消费”。如果直接把 `normalized.structured.json` 的 `text.full_text` 当成单篇精读的唯一阅读源，就会把页码、页眉、重复标题、front matter、参考文献尾段和跨页噪声一起送入模型，最终污染标准文献笔记和后续分析笔记。

因此，A070 的理论设计必须先回答两个问题：

1. 单篇综述到底应该按什么顺序阅读哪些输入层。
2. 多篇综述的综合分析笔记到底如何从“单篇标准文献笔记”上升为“真正的研究综合”。

## 二、设计目标

本设计面向通用学术科研场景，不限定经济学、管理学或某一具体学科。

目标如下：

1. 为单篇综述阅读建立统一、稳定、可审计的输入分层与阅读顺序。
2. 为标准文献笔记建立通用的章节规范与引文支撑规范。
3. 为跨综述分析笔记建立通用的综合逻辑，而不是普通笔记的简单拼接。
4. 为 A080 提供结构化、可传递、可导出的普通文献待读清单生成逻辑。
5. 为后续 AOK tools 和 A070 affair.py 改造提供清晰的理论上位约束。

## 三、核心原则

### 3.1 单篇综述阅读必须是分层阅读，不是单文件通读

模型不应直接读取“某个目录下所有文件的拼接结果”，而应按信息密度与噪声风险分层读取。

### 3.2 单篇综述处理必须是一文一上下文

每篇综述必须由单文献独立 worker 处理。一个 worker 只读一篇综述，不共享上一篇综述的上下文，不把多篇综述全文拼给一个持续会话。

### 3.3 标准文献笔记必须是证据支撑型笔记

笔记中的每一个陈述句都必须在句尾给出 cite_key 形式的支撑，引文作用是说明“该句判断依据于哪篇文献或哪组文献”，而不是把长原文、页码噪声和调试信息直接写进正文。

### 3.4 综合分析笔记必须是研究综合，不是段落拼接

综合分析笔记必须显式完成比较、归纳、分层、解释和外推，不能只是把各篇综述的要点按顺序堆起来。

### 3.5 解析资产应坚持“结构层优先，原文 PDF 按需回看”

只要结构化资产足够可用，模型应优先消费经过结构过滤的正文层；只有在模型明确判断关键证据不足、结构层含混或需要核验图表/布局时，才按需回调原文 PDF 或页图。

## 四、单篇综述阅读输入设计

### 4.1 输入分层总览

单篇综述 worker 的输入应分为四层：

1. 定位层：文献主表字段。
2. 主阅读层：经结构过滤后的正文文本包。
3. 证据补充层：参考文献、原文页图、局部 PDF 回看。
4. 审计层：解析记录与质量报告。

这四层的职责不同，不能混用。

### 4.2 第一层：定位层

进入正文阅读前，模型应先读取文献主表中的核心字段，用于建立阅读意图与主题边界。

建议最小字段集合：

1. `uid_literature`
2. `cite_key`
3. `title`
4. `abstract`
5. `keywords`
6. `year`
7. `authors`
8. `venue` 或 `source`
9. `structured_status`
10. `structured_abs_path`

这一步的作用不是写笔记，而是让模型先回答三个问题：

1. 这篇综述讨论的核心对象是什么。
2. 这篇综述可能覆盖哪些理论、方法或实证主题。
3. 这篇综述值得优先关注哪些章节与证据类型。

### 4.3 第二层：主阅读层

单篇综述的主阅读层不应直接使用 `normalized.structured.json.text.full_text`，而应由预处理工具从以下文件构造“精读包”。

推荐顺序如下：

1. `structured_tree.json`
2. `elements.json`
3. `linear_index.json`

这三层的分工如下：

1. `structured_tree.json` 用于识别文档结构边界。
2. `elements.json` 用于提取标题、正文段落、摘要、关键词等细粒度文本。
3. `linear_index.json` 用于恢复正确的阅读顺序、页码落点和元素映射关系。

在模型真正阅读前，应由工具层先生成一个“单篇综述精读包”，建议最少包含以下内容：

1. `orientation.json`
2. `clean_body.md`
3. `evidence_index.jsonl`
4. `references.jsonl`
5. `asset_manifest.json`

其中：

1. `orientation.json` 保存主表关键字段与本次阅读任务上下文。
2. `clean_body.md` 是去掉噪声后的正文 Markdown 主阅读文本。
3. `evidence_index.jsonl` 保存每一段正文的 section、subsection、page、node_id、element_id 等证据定位信息。
4. `references.jsonl` 保存结构化提取的参考文献条目。
5. `asset_manifest.json` 保存可按需回调的 PDF、页图、附件路径与解析状态。

### 4.4 正文过滤规则

`clean_body.md` 的生成必须至少执行以下过滤：

1. 过滤 `front_matter` 节点。
2. 过滤 `收稿日期`、`作者简介`、分类号、DOI、页眉、刊名、页码标签。
3. 过滤参考文献 section 及其后续非正文节点。
4. 合并或去重重复标题，例如 `引言引言`。
5. 保留真正的 section、subsection、heading 和正文 paragraph。
6. 对跨页截断段落做拼接修复。
7. 对异常长句、异常短句、目录串句做切分或剔除。

### 4.5 第三层：证据补充层

当模型已读完主阅读层，但认为仍需要补证时，允许按需读取以下内容：

1. `normalized.structured.json.references`
2. `reconstructed_content.md`
3. `attachments_manifest.json`
4. 页图 PNG/JPEG
5. 原始 PDF

这一步必须是“按需调用”，而不是默认全文重读。

允许触发补证的典型情形：

1. 章节边界不清楚。
2. 某一关键结论在正文层存在断裂或截断。
3. 需要确认图表、表格或嵌入图片中的信息。
4. 需要核验参考文献区是否被误拼接进正文。

### 4.6 第四层：审计层

以下文件不应用于直接写笔记，但应参与运行审计：

1. `parse_record.json`
2. `quality_report.json`
3. `result.json`

它们的作用是说明：

1. 本次解析是否真实调用了模型。
2. 用了哪个模型和后端。
3. 解析页数、元素数、chunk 数是否合理。
4. 当前资产是否适合直接进入单篇综述阅读。

## 五、单篇综述 worker 理论流程

### 5.1 流程概览

单篇综述 worker 的理论流程应为：

1. 读主表字段，建立主题预判。
2. 读精读包主阅读层，完成章节化阅读。
3. 若必要，按需回调局部 PDF 或页图。
4. 形成标准文献笔记草稿。
5. 对草稿执行引文支撑与格式审计。

### 5.2 阶段一：主题定向

模型先基于标题、摘要、关键词、年份与来源回答：

1. 这是一篇什么类型的综述。
2. 它主要覆盖哪些研究对象、机制、方法或情境。
3. 阅读时最应重点关注哪些部分。

### 5.3 阶段二：正文精读

模型在 `clean_body.md` 上完成正文精读，不逐句摘抄，而是围绕以下六类任务抽取证据：

1. 研究脉络
2. 核心成果
3. 共识点
4. 争议点
5. 未来方向
6. 知识框架

如果保留原有标准文献笔记中的“研究问题”“研究方法与证据”等章节，也应把它们视为基础章节，而不是替代上述六个必备章节。

### 5.4 阶段三：按需补证

如果模型判断某个判断缺乏足够正文支撑，可以回调：

1. 参考文献区
2. 页图
3. 原始 PDF 局部页

补证后重新修订相应句子，而不是整篇重写。

### 5.5 阶段四：标准文献笔记成稿

单篇综述标准文献笔记建议至少包含以下章节：

1. 文献信息
2. 研究问题与对象界定
3. 研究方法与证据来源
4. 研究脉络
5. 核心成果
6. 共识点
7. 争议点
8. 未来方向
9. 知识框架
10. 参考文献列表

其中：

1. 第 4 到第 9 节为 A070 必备增量内容。
2. 第 10 节必须保留 `[[cite_key]]` 回链，不得删除。

### 5.6 单篇笔记的引文写法

单篇综述标准文献笔记中的每一个陈述句都必须在句尾追加 cite_key 引文。

建议正文最小格式为：

1. `……（cite_key: 当前综述cite_key）`

不建议继续把以下噪声直接写入正文：

1. 原文长句全文复制。
2. 句序调试号。
3. 大段页码与 front matter 文本。

如果某一句明确是在复述某篇被综述文献中点名讨论的原始研究，并且该原始研究已在本地文献库匹配出 cite_key，则可以使用增强格式：

1. `……（cite_key: 当前综述cite_key；supporting_ref: 原始研究cite_key）`

但增强格式应谨慎使用，以免正文可读性下降。

## 六、跨综述分析笔记理论设计

### 6.1 输入边界

跨综述分析笔记的主输入应是“已完成的单篇标准文献笔记”，而不是多篇综述原始 PDF 或多份未经清洗的 structured 结果。

允许的主要输入：

1. 各篇综述标准文献笔记中的结构化章节。
2. `reference_citation_mapping.csv`。
3. `must_read_originals.csv`（审计导出件）。
4. `review_general_reading_list.csv`（审计导出件）。
5. 各篇综述对应的 cite_key 与基础元数据。

### 6.2 综合分析不是简单拼接

综合分析笔记必须完成以下至少三类学术操作：

1. 比较：比较不同综述对同一主题的界定、归因或结论。
2. 归纳：把多篇综述中反复出现的稳定判断抽象为更高层命题。
3. 解释：说明为什么会出现分歧、边界条件或研究空白。

因此，综合分析笔记不能按“综述 A 一段 + 综述 B 一段 + 综述 C 一段”的方式生成。

### 6.3 六类分析笔记的理论任务

#### 6.3.1 研究脉络

任务不是罗列时间顺序，而是回答：

1. 研究对象如何被逐步界定。
2. 理论解释如何演进。
3. 方法工具如何迁移或升级。
4. 问题意识如何从描述走向机制解释与政策应用。

#### 6.3.2 核心成果

任务是提炼当前主题下已较为稳定成立的关键认识。

这要求把“多篇综述都支持、且表达方式不同但含义一致”的命题压缩成少数高质量判断。

#### 6.3.3 共识点

共识点不是“只要出现过就算”，而应满足最小阈值。

建议共识识别标准：

1. 至少两篇及以上独立综述明确支持。
2. 支撑句不来自同一篇综述内部的重复改写。
3. 命题具有共同主题中心，而非偶然词语重叠。

#### 6.3.4 争议点

争议点应围绕“同一主题下的不同判断”来写，而不是泛泛写“学界存在争议”。

争议来源建议至少分为：

1. 样本与情境差异。
2. 指标与测量差异。
3. 理论视角差异。
4. 方法与识别策略差异。
5. 时期与制度背景差异。

#### 6.3.5 未来方向

未来方向不是简单抄写综述末尾“未来研究可进一步……”的话，而应转化为可执行研究议程。

每个未来方向最好回答：

1. 缺的是什么证据。
2. 为什么当前研究还不足。
3. 未来应补哪种数据、方法、比较对象或理论连接。

#### 6.3.6 知识框架

知识框架应把多篇综述中的知识组织为一个结构化框架，建议至少包含：

1. 核心对象
2. 关键机制
3. 情境与边界
4. 方法与证据
5. 结果与含义
6. 未解问题

知识框架的结果形态可以是：

1. 分层条目式框架。
2. 概念-机制-结果框架。
3. 面向后续 A080 的普通文献选题导向框架。

### 6.4 综合分析笔记的引文规则

综合分析笔记中的每一个陈述句同样必须在句尾保留 cite_key 支撑。

建议格式：

1. 单综述支撑句：`……（cite_key: 综述A）`
2. 多综述综合句：`……（cite_key: 综述A | 综述B | 综述C）`

当一句话已经是跨综述综合判断时，禁止只保留其中一篇综述的 cite_key。

## 七、A080 普通文献待读清单理论设计

### 7.1 生成目标

A070 的输出不应止于综述分析，还必须把综合结果转化为后续普通文献的阅读入口。

### 7.2 最小输出形式

A080 待读清单应至少同时支持：

1. 写回 content.db 的 reading queue。
2. 导出一份 CSV。
3. 可选导出一份 Markdown 版说明清单。

### 7.3 交接原则

普通文献正式交接主线统一为：A070 只正式交给 A080，A080 再顺序推进到 A090。

因此本节口径调整为：

1. A070 负责生成候选导出件与 A080 正式入口。
2. A080 负责预处理、标准化和进入 A090 的顺序推进。
3. A090 只消费经过 A080 处理的条目，不接受 A070 的直接交接。

### 7.4 清单字段建议

建议最少字段如下：

1. `uid_literature`
2. `cite_key`
3. `title`
4. `recommended_reason`
5. `theme_relation`
6. `bucket`
7. `target_stage`
8. `priority`
9. `source_review_cite_keys`

## 八、对 A070 程序设计的上位约束

本理论设计对程序层提出以下硬约束：

1. 单篇综述主阅读源必须改为“结构过滤后的精读包”，而不是直接吃 `full_text`。
2. 单篇标准文献笔记必须新增或稳定回填六个核心章节：研究脉络、核心成果、共识点、争议点、未来方向、知识框架。
3. 正文句末引文必须简化为可读的 cite_key 形式，不能继续回填调试型长引文。
4. 综合分析笔记必须基于单篇标准文献笔记进行二次综合，而不是基于原始句子做规则拼装。
5. A080 入口候选必须同时完成数据库传递与可导出文件输出。
6. 原始 PDF 和页图必须变成按需补证工具，而不是默认主输入。
7. 审计层必须能说明：本次单篇阅读是否使用结构化主链、是否触发原文 PDF 回看、哪些条目因缺解析资产而被跳过。

## 九、最终结论

A070 的合理设计不是“让模型直接读解析目录”，而是“先由工具层为单篇综述构造干净、可定位、可回证的阅读包，再由单文献 worker 完成标准文献笔记，最后基于标准笔记完成跨综述综合分析”。

对通用学术科研而言，更稳健的单篇综述阅读顺序应为：

1. 先读文献主表核心字段。
2. 再读由 `structured_tree.json + elements.json + linear_index.json` 生成的正文精读包。
3. 再按需回调参考文献、页图与原始 PDF。
4. 最后写带 cite_key 支撑的标准文献笔记。

而更稳健的综合分析顺序应为：

1. 先汇总单篇标准文献笔记。
2. 再围绕研究脉络、核心成果、共识点、争议点、未来方向和知识框架做跨综述综合。
3. 最后据此生成提供给 A080 的普通文献待读清单，并由 A080 顺序推进到 A090。

这才是固定流程型为基础、分析型为核心的 A070 理论模型。
