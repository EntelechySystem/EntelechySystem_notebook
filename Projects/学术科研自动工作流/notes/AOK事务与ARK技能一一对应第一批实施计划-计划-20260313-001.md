# AOK事务与ARK技能一一对应第一批实施计划-计划-20260313-001

## 一、目标

- 以 `.opencode/skills/` 为唯一上游能力清单，建立 ARK 技能与 AOK 事务的一一对应收口机制。
- 落地第一批基础设施：统一桥接 helper 与三侧一致性校验。
- 将映射表转为可执行任务清单，作为后续批次的实施入口。

## 二、helper 放置规则（按共识确认）

### 2.1 放置原则

1. 如果桥接逻辑服务于 ARK 技能调用 AOK 事务，则 helper 放在 ARK 的 `academicresearch_kit/tools/`。
2. 如果能力是 AOK 事务直接使用的公共工具，则放在 AOK 的 `autodokit/tools/`。
3. 如果能力属于 AOK 流程图框架、运行时注册、调度与治理基础设施，则放在 AOK 的 `autodokit/utils/`。
4. 桥接 helper 不承载业务算法，只处理调用协议、参数标准化与结果标准化。

### 2.2 本轮落位

- 已落位：`academicresearch_kit/tools/aok_affair_bridge.py`
- 原因：该 helper 是 ARK 技能层对 AOK `run_affair` 的统一桥接，不属于 AOK 事务业务工具。

## 三、统一接口草案（第一版）

### 3.1 helper 入口

- 函数：`run_aok_affair_skill(...)`
- 关键参数：
  - `skill_id`：opencode 技能 ID
  - `affair_uid`：AOK 事务 UID
  - `config`：事务配置字典
  - `workspace_root`：工作区根目录
  - `strict`：AOK 严格模式开关

### 3.2 统一返回结构

- `status`：执行状态
- `mode`：技能模式（默认等于 `skill_id`）
- `skill_id`：技能 ID
- `affair_uid`：事务 UID
- `artifacts`：事务产物绝对路径列表

### 3.3 设计约束

1. ARK 技能层不再直接调用 ARK 私有 engine 实现业务逻辑。
2. ARK 技能层允许做参数兼容与输入预处理，但必须最终落到 `run_aok_affair_skill(...)`。
3. AOK 事务是业务实现唯一事实来源。
