## 一、背景与目的

- 背景：ARK 到 AOK 的迁移已推进到 API 门面化阶段，历史“未接入技能”文档口径偏旧。
- 目的：按当前代码状态，重新给出“ARK 技能中尚未从 AOK affairs 接入”的清单，区分迁移完成项与待接入项。

## 二、盘点口径

- 扫描范围：`academicresearch_kit/skills/*.py`、`academicresearch_kit/api/*.py`。
- “已从 AOK affairs 接入”判定：技能通过 `academicresearch_kit.api.*` 间接解析到 `autodokit.affairs.*`。
- “未从 AOK affairs 接入”判定：技能逻辑仍在 ARK 本地实现，或仅接入 AOK 非事务模块（如 `autodokit.scheduling` / `autodokit.taskdb`）。

## 六、结论

- 迁移主干已完成：检索治理、本地文献导入、知识预筛选、文献阅读规划、CNKI 桥接五类事务已经通过 ARK API 门面接入 AOK。
- P0 首批已完成：`method_whitelist_selection`、`integrity_check`、`rag_evidence_synthesis` 已切换到 AOK affairs 门面。
- 当前“未从 AOK affairs 接入”的技能仍较多，主要集中在：计量分析、写作、环境与路由、项目初始化等能力。
- 下一步建议优先把“跨项目可复用且可参数化”的能力事务化，减少 ARK 技能层重复实现。

## 七、建议优先级

1. P0：`method_whitelist_selection`、`integrity_check`、`rag_evidence_synthesis`（已完成接入）
2. P1：`did_rdd_pipeline`、`empirical_four_pack`、`variable_operationalization`（核心研究流水线）
3. P1：`paper_draft`、`revision_response`（写作闭环）
4. P2：`workspace_sanity_check`、`project_bootstrap`、`model_routing_dispatch`（工程支撑能力）
