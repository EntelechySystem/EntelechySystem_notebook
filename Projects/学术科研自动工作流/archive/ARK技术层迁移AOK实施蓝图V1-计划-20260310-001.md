# ARK技术层迁移AOK实施蓝图V1-计划-20260310-001

## 0. 目标与硬约束

### 0.1 目标

将 ARK 的工作流技术层（流程图解析/构建、节点运行时、调度计算、任务事务账本与回放、通用工具）统一迁移到 AOK；ARK 仅保留学术科研领域语义、流程设计与高阶决策。

### 0.2 硬约束（本计划强制）

- 不做兼容保留：迁移完成后立即删除 ARK/AOK 冗余实现与重复入口。
- 不保留历史兼容壳：如 `scheduler_core`、`tasking_db` 迁移完成后直接删除。
- 唯一留痕：任务日志（task log）与 Git 历史。
- 重复基础工具优先保留 AOK：路径解析、配置加载、workflow 路径解析等通用能力一律以 AOK 为准。

### 0.3 迁移范围边界

- 迁移到 AOK：技术引擎能力。
- 保留在 ARK：学术领域能力与流程设计语义。
- ARK 通过生成 `workflow.json`/`aof.md` 与调用 AOK API/CLI 使用引擎，不再维护自有引擎实现。

## 3. 迁移步骤与删除动作（严格执行）

## 步骤 S1：删除兼容壳并修正引用

1. 删除：`academicresearch_kit/scheduler_core/`
2. 删除：`academicresearch_kit/tasking_db/`
3. 全仓替换导入为正式路径（或 AOK 新路径）。
4. 删除所有“兼容层”文档说明。

验收标准：
- 结果一致性：核心 CLI 调度与 taskdb 操作输出与删除前一致。
- 回放一致性：`ReplayEngine` 对同一 run 数据回放结果一致。
- 日志字段一致性：事件日志字段集合不减少。

## 步骤 S2：基础工具归一到 AOK

1. 在 AOK 完成 project runtime 与 flow trace 的统一实现。
2. ARK 删除 `tools/project_runtime.py`、`tools/flow_trace.py`，改由 AOK 导入。
3. ARK `tools/__init__.py` 改为仅导入 AOK 工具或删除对应导出。

验收标准：
- 结果一致性：`resolve_workspace_root`、`load_dispatch_map` 等行为一致。
- 回放一致性：trace 文件可被 taskdb 回放器正确消费。
- 日志字段一致性：保留字段 `timestamp/command/agent/skill/provider/model/task_uid/transaction_uid/status/mode/artifacts`。

## 步骤 S3：调度引擎迁入 AOK

1. 在 AOK 新建 `autodokit/scheduling/*` 并迁入 ARK `domains/scheduling/*`。
2. AOK `main.py` 与 `node_runtime_v2.py` 接入调度链。
3. ARK 删除 `domains/scheduling/*` 实现，改为调用 AOK 调度。
4. ARK `skills/scheduler_dispatch.py` 改为 AOK 调度 API 封装。

验收标准：
- 结果一致性：同输入下 `selected_transaction_uid` 一致。
- 回放一致性：调度事件重放后序列一致（event_uid 可不同，事件语义字段一致）。
- 日志字段一致性：`selection/guard_decision/receipt` 三段结构完整。

## 步骤 S4：taskdb 引擎迁入 AOK

1. 在 AOK 新建 `autodokit/taskdb/*` 并迁入 ARK `platform/taskdb/*`。
2. AOK 运行链路写入 taskdb 执行记录。
3. ARK 删除 `platform/taskdb/*`，改为调用 AOK taskdb。
4. ARK `api/taskdb.py` 仅保留 AOK 代理层。

验收标准：
- 结果一致性：Bootstrap、Integrity、Snapshot、Replay 结果一致。
- 回放一致性：同 run 数据重放任务状态机转移一致。
- 日志字段一致性：task/transaction/edge/result_code/audit_result 字段齐全。

## 步骤 S5：领域引擎事务化迁移（分批）

1. 将 ARK domains 按事务颗粒封装至 AOK affairs。
2. ARK skills 改为调用 AOK affairs。
3. 迁移完成即删除 ARK 对应 domains 实现文件。

验收标准：
- 结果一致性：同输入文献/数据，输出结构字段一致。
- 回放一致性：事务执行记录可在 AOK taskdb 全链回放。
- 日志字段一致性：每个事务均输出统一 run 记录与 artifact 清单。

## 4. 验收体系（统一口径）

### 4.1 结果一致性

- 定义：同一输入、同一配置下，新旧链路产物结构与关键字段一致。
- 检查项：
  - workflow 选路结果。
  - taskdb 状态机终态。
  - 领域事务输出 JSON 字段。

### 4.2 回放一致性

- 定义：同一执行日志在回放引擎重建出的状态转移图一致。
- 检查项：
  - task 状态轨迹。
  - transaction 状态轨迹。
  - guard 决策轨迹。

### 4.3 日志字段一致性

- 定义：统一日志 schema 必须完整，不允许字段退化。
- 必填字段：
  - `timestamp`
  - `command`
  - `agent`
  - `skill`
  - `provider`
  - `model`
  - `task_uid`
  - `transaction_uid`
  - `status`
  - `mode`
  - `artifacts`
- 调度扩展字段：
  - `selection`
  - `guard_decision`
  - `receipt`

## 7. 风险与控制

1. 风险：一次性替换导致路径中断。
- 控制：按步骤批量迁移，每步都跑一致性验收。

2. 风险：日志 schema 漂移导致回放失败。
- 控制：先冻结日志字段 schema，再迁移写入实现。

3. 风险：事务颗粒过粗影响调度精度。
- 控制：按学术流程拆分事务，优先保证输入输出契约稳定。

## 8. 完成定义（DoD）

- AOK 成为唯一技术引擎承载层（流程图、调度、taskdb、通用工具）。
- ARK 不再含任何技术引擎重复实现。
- ARK 仅保留科研语义与流程设计。
- 三类验收（结果一致性、回放一致性、日志字段一致性）全部通过。
