# 文献管理系统讨论纪要-备忘-20260304-001

## 一、背景与目标

本轮讨论的核心目标是：

1. 将文献库从普通数据目录中独立出来，形成专门的文献资产体系。
2. 明确“原始文献”与“规范化文献”的分层规则。
3. 统一命名规范，减少后续脚本、LLM、人工协作中的歧义。
4. 把路径口径同步到规则、代理、技能、白名单和项目文档。

## 二、关键决策（已确认）

### 1) 文献库主路径

- 不使用 `data/references`。
- 文献数据库主目录固定为：`references/`。

### 2) 文献分层结构

采用两层主流程：`origin -> normal`。

- `references/origin/`：原始非结构化文献（只进不改）
- `references/normal/`：处理后的规范化文献资产
- `references/logs/`：文献处理日志

### 3) 原始文献来源子目录命名（使用 `ai` 字眼）

在 `references/origin/` 下使用：

- `user_uploads/`：用户上传原始文献
- `ai_web_oa/`：AI 联网获取的 OA 原始文献
- `ai_web_subscription_meta/`：AI 仅获得的订阅题录/元数据
- `ai_web_subscription_files/`：经人工授权后获取的订阅原文

### 4) 规范化文献子目录

在 `references/normal/` 下使用：

- `bib/`：规范化题录
- `fulltext/`：规范化原文
- `notes/`：结构化笔记
- `manifest/`：文献台账

### 5) 批次命名建议

原始导入批次目录建议格式：

`YYYYMMDD_来源_主题_批次号`

示例：

- `20260304_user_房地产系统性风险_b01`
- `20260304_cnki_限购政策_b02`
- `20260304_openalex_riskspillover_b01`

## 三、关于 manifest 的统一认知

### 1) manifest 的含义

- `manifest` 本意是“清单/载货单/登记表”。
- 在本项目中，它是文献元数据与审计信息的台账文件。

### 2) manifest 与 BibTeX 的关系

- BibTeX 负责文献题录交换（如作者、标题、年份、期刊、DOI）。
- manifest 是项目自定义台账，负责补充 BibTeX 不涵盖的信息（来源、权限、文件路径、哈希、状态等）。

### 3) manifest 是否是数据库

- 可视为“轻量文件型数据库（元数据索引）”。
- 非关系型数据库，但具备检索、更新、追溯能力。

### 4) JSON 与 CSV 的讨论结论

- JSON：结构灵活、易被 LLM 与脚本直接消费。
- CSV：更适合人工在 Excel 快速批量编辑。
- 讨论建议：后续可采用“双格式策略”（JSON 主存 + CSV 编辑视图 + 同步脚本）。
