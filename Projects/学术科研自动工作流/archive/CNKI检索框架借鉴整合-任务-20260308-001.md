# CNKI检索框架借鉴整合-任务-20260308-001

## 1. 任务背景

本任务基于 `report-CNKI技能对OpenCode与ARK借鉴分析-20260308-001.md` 与 `plan-CNKI检索能力整合落地计划-20260308-001.md` 开展，目标是把 `cnki-skills` 中适合当前 OpenCode + ARK 体系的内容，优先以“框架完整、协议细致、实现占位可扩展”的方式借鉴进本仓库。

本轮不追求一步到位实现完整浏览器自动化，而是优先完成：

1. OpenCode 侧 CNKI 专项 skill 框架。
2. ARK 侧 CNKI 结构化数据模型与规划引擎。
3. 文档、代理说明与公开 API 的同步。

## 2. 可行性分析

### 2.1 可直接落地的部分

1. `cnki-skills` 的技能切片方式。
2. 各子事务的输入参数、输出字段与中断原因设计。
3. 导出、下载、期刊评价、刊期目录等较细颗粒度框架。
4. 与 `retrieval-governance`、`local-reference-ingestion`、`knowledge-prescreen` 的衔接接口。

### 2.2 当前只能先占位的部分

1. 面向实际浏览器页面的执行脚本。
2. 真正的 CNKI 登录态、验证码、标签页切换与下载触发。
3. Zotero 等第三方软件的正式接入。

这些内容本轮先通过结构化占位字段和标准脚本入口保留扩展位，不破坏当前分层。

## 3. 计划步骤

1. 在 ARK 中新增 CNKI 结构化模型与统一规划器。
2. 在 ARK 中新增 CNKI 10 项 skill 入口。
3. 在 OpenCode 中新增 CNKI 10 项技能目录与脚本包装。
4. 更新 `cn-literature-retriever`，让其纳入 CNKI 专项技能链。
5. 同步 README、开发者指南和 API 手册。

## 5. 当前结果

本轮完成的是“全方位借鉴的第一阶段骨架化落地”，而不是“CNKI 浏览器自动化已经全部打通”。

已经完成的关键成果：

1. `cnki-skills` 中最有价值的技能切片，被正式迁入当前 OpenCode 技能层。
2. 这些技能没有直接绑定 Claude 语法，而是改造成 OpenCode + ARK 的分层形式。
3. ARK 已经具备承接 CNKI 检索、期刊、目录、下载、导出等结构化结果的能力。
4. 将来接入真实页面执行器、Zotero、RIS 文件落地时，不需要再推翻当前结构。
