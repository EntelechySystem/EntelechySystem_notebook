# ARK独立干测试-任务-20260308-001

## 任务背景

用户要求对 ARK（`academicresearch_kit`）的每一个功能尝试进行一次单独的干测试，重点验证这些能力在不依赖 `opencode` 的独立情况下是否能够运作。

本轮运作同时使用了用户提供的测试样本目录：

- `references/origin/user_uploads`

本轮测试遵循以下边界：

- 只测试当前仓库中已经脚本化、可直接通过 Python 包入口或 CLI 入口调用的功能。
- 不把 `.opencode/skills/*` 作为必要依赖。
- 尽量使用 dry-run、decision-only、非执行模式或最小样本模式，避免引入外部 API、副作用执行和无关写入。
- 测试程序统一放入 `academicresearch_kit/demos/`，测试产物统一放入 `demos/ark_standalone_drytest_20260308_001/` 与 `demos/ark_regression/`，降低对正式运行目录的干扰。

## 需求分析

本任务的核心不是验证 OpenCode 调用链是否正常，而是验证 ARK 自身是否已经具备“脱离 OpenCode 独立运行”的最小可用性。

结合当前仓库结构，ARK 的功能入口分为两层：

- 包内 skill/engine 入口：`academicresearch_kit.skills.*`
- 对外公开 CLI：`academic-research-kit`、`ark-scheduler`、`ark-taskdb-bootstrap`、`ark-taskdb-validate`、`ark-taskdb-replay`、`ark-retrieval`

因此，本任务可行，且适合拆成两类测试：

1. 包内可脚本化功能干测试
2. 公开 CLI 独立烟雾测试

## 可行性分析

本任务可行，原因如下：

- 仓库内已有完整 Python 包结构，且 `.venv` 可正常导入 `academicresearch_kit`。
- `pyproject.toml` 已注册对外 CLI，可直接绕开 `opencode` 执行。
- `academicresearch_kit/skills/README.md` 已明确列出当前“已脚本化接入”的功能范围。
- 用户已提供 `references/origin/user_uploads`，足以覆盖本地文献导入、知识预筛选和文献阅读计划这条链路的样本输入。

同时存在以下客观边界：

- `model-routing-dispatch` 的真实外部调用依赖有效 API Key，本轮仅测试 `decision-only` 模式。
- `scheduler-dispatch` 与 `ark-scheduler` 本轮验证的是调度闭环与派发回执生成，不包含真实目标执行。
- `ark-workflow-executor` 本轮使用 `dry_run=True`，验证的是配置读取、workflow 解析和摘要能力，不是全量事务执行。
- 文档型、未脚本化能力不属于“可独立执行功能”，因此不纳入本轮测试通过/失败统计。

## 计划

1. 盘点 ARK 当前可独立运行的功能入口。
2. 区分包内功能入口与公开 CLI，形成测试矩阵。
3. 检查 `.venv` 与关键依赖，确保在项目推荐环境中执行测试。
4. 在 `sandbox/` 下建立隔离测试目录，避免污染现有数据。
5. 编写独立干测试脚本，逐项调用 ARK 包内已脚本化功能。
6. 运行公开 CLI 的独立烟雾测试。
7. 汇总结果、记录风险边界，并输出任务文档。

## 风险与边界

尽管本轮测试整体通过，但仍需注意以下边界：

- 本轮属于干测试，不等于真实业务全链路执行测试。
- `academic-research-kit` 只验证了 `dry-run` 摘要，不代表 workflow 中所有事务实现都已真实执行通过。
- `scheduler_dispatch` 与 `ark-scheduler` 只验证了非执行模式回执，不代表所有派发目标都已真实执行通过。
- `model_routing_dispatch` 只验证了 `decision-only`，未验证真实外部模型调用。
- 文档型、未脚本化 skill 仍不能算作“可独立运行功能”，需要后续继续脚本化。
