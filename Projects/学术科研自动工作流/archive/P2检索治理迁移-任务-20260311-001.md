# P2检索治理迁移-任务-20260311-001

## 一、任务背景与目标

- 背景：在 S5 阶段进入 P2，需要将 ARK 中 `retrieval_governance` 的实现从 `academicresearch_kit/domains` 迁移到 AOK 事务层，延续“ARK 门面 + AOK 实现”的单一实现源模式。
- 目标：
  - 在 AOK 新增可运行的 `检索治理` 事务实现。
  - 保持 ARK 对外 API 与 skill 调用契约稳定。
  - 删除 ARK 旧域实现，避免双实现并存。
  - 完成迁移后静态校验与收口记录。

## 二、可行性分析

### 2.1 现状评估

- ARK 现状：`academicresearch_kit/api/retrieval.py` 迁移前仍直接引用 `academicresearch_kit.domains.retrieval_governance`。
- AOK 现状：`autodokit/affairs/` 下迁移前无 `检索治理` 事务，需要新增。
- 风险点：
  - 删除旧目录后可能残留字符串型调度目标（非 import 语句）。
  - 若 ARK 门面路径不稳定，会影响 scheduler/skill 的派发可用性。

### 2.2 迁移策略

- 采用与 P1 一致策略：
  - AOK 新增事务承接实现。
  - ARK API 改为动态解析 AOK 符号。
  - 调度默认 target 统一收敛到 ARK 稳定门面路径。
  - 删除 ARK 旧 domain 实现并做残留检查。

### 2.3 可行性结论

- 可行。迁移对象边界清晰，外部契约可通过门面保持稳定；改动集中在少量文件，便于验证与回滚。

## 三、实施计划

1. 盘点 ARK 现有 retrieval_governance 代码与引用点。
2. 在 AOK 新增 `autodokit/affairs/检索治理` 事务四件套。
3. 修改 ARK `api/retrieval.py`，切换为动态门面解析 AOK 符号。
4. 修正 scheduler 相关字符串目标，统一指向 `academicresearch_kit.api.retrieval:default_retrieval_handler`。
5. 删除 ARK 旧目录 `academicresearch_kit/domains/retrieval_governance`。
6. 执行残留引用扫描与错误检查。
7. 记录结果并给出下一步建议。
