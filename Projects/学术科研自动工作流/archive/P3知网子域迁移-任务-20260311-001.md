# P3知网子域迁移-任务-20260311-001

## 一、任务背景与目标

- 背景：S5 阶段已完成 P2（检索治理迁移），当前剩余 ARK `domains` 中唯一技术实现为 `cnki` 子域。
- 目标：
  - 将 ARK `academicresearch_kit/domains/cnki` 迁移到 AOK 事务层。
  - 保持 ARK skill 与包级导出契约稳定（外部调用路径不变）。
  - 删除 ARK 旧 `domains/cnki` 实现，确保单一实现源。
  - 完成代码静态校验与文档同步收口。

## 二、可行性分析

### 2.1 现状评估

- ARK 现状：
  - `skills/cnki_bridge.py` 直接依赖 `academicresearch_kit.domains.cnki`。
  - `academicresearch_kit/__init__.py` 包级导出也直接依赖 `domains.cnki`。
- AOK 现状：
  - 暂无可直接承接上述符号的事务包。

### 2.2 风险点

- 动态门面切换后，类型标注若继续把符号当静态类型使用，可能出现类型表达式错误。
- CNKI 模块包含 planner/runtime/models/artifacts 多文件，迁移时需保证内部导入路径自洽。

### 2.3 迁移策略

1. 在 AOK 新建 `autodokit/affairs/CNKI桥接`，承接 `cnki` 子域实现。
2. 在 ARK 新建 `api/cnki.py` 动态门面，导出原有关键符号。
3. `skills/cnki_bridge.py` 与 `academicresearch_kit/__init__.py` 切换到 `api/cnki.py`。
4. 删除 ARK `domains/cnki`。
5. 运行残留扫描与错误检查，修复类型层回归。

### 2.4 可行性结论

- 可行。变更集中在门面与导入链，外部 skill 契约可保持不变；删除后可通过残留扫描与错误检查闭环。

## 三、实施计划

2. 修正 AOK 包内导入并补 `affair.py`、`affair.json`、`affair.md`。
3. 新增 ARK `api/cnki.py` 门面导出。
4. 修改 ARK `skills/cnki_bridge.py` 与包级 `__init__.py` 导入路径。
5. 删除 ARK `domains/cnki`。
6. 校验：残留引用扫描 + 错误检查。
7. 同步 `autodo-kit/docs/API手册.md`。
